# Поиск по книге и единые панели reader-а

Status: ready-for-agent

## Problem Statement

В режиме чтения пользователь не может искать текст внутри открытой книги. Верхняя панель reader-а не предоставляет единого места для поиска и управления позицией чтения, а PDF не позволяет перейти к конкретной странице. На touch-устройствах скрытые панели невозможно открыть наведением или горячей клавишей.

## Solution

Добавить единый reader-контроллер верхней и нижней панелей для FB2 и PDF. Панели будут фиксированными, компактными, однострочными и отображаться одновременно.

В нижней панели разместить поиск по книге слева. Поиск запускается только клавишей `Enter` или кнопками перехода к следующему/предыдущему совпадению. Результаты подсвечиваются в тексте, активное совпадение прокручивается примерно в центр экрана, а навигация по результатам циклическая.

Для FB2 в нижней панели показывать процент прочитанного. Для PDF показывать текущую физическую страницу и общее количество страниц в виде `[текущая] / всего`; номер страницы можно вводить и подтверждать `Enter` или потерей фокуса.

## User Stories

1. Как читатель, я хочу искать текст в открытой FB2-книге, чтобы быстро находить нужный фрагмент.
2. Как читатель, я хочу искать текст в открытой PDF-книге, чтобы быстро находить нужный фрагмент.
3. Как читатель, я хочу использовать собственную панель поиска reader-а, чтобы поиск не зависел от стандартного поиска браузера.
4. Как читатель, я хочу видеть строку поиска только в нижней панели reader-а, чтобы интерфейс не занимал место отдельной кнопкой открытия поиска.
5. Как читатель, я хочу нажать `Ctrl+F` или `Cmd+F`, чтобы обе панели открылись, а поисковый input получил фокус.
6. Как читатель, я хочу, чтобы при получении фокуса весь сохранённый текст input автоматически выделялся для быстрой замены запроса.
7. Как читатель, я хочу, чтобы простое изменение текста в input не запускало поиск и не меняло текущие результаты.
8. Как читатель, я хочу запускать поиск клавишей `Enter`, чтобы не искать при каждом введённом символе.
9. Как читатель, я хочу запускать поиск кнопками «Найти следующее» и «Найти предыдущее», чтобы перемещаться между результатами без повторного ввода запроса.
10. Как читатель, я хочу, чтобы кнопки поиска использовали актуальный текст input только после явного действия поиска.
11. Как читатель, я хочу искать без учёта регистра, чтобы запрос находил варианты с разным регистром.
12. Как читатель, я хочу искать обычные подстроки без режима регулярных выражений, чтобы поиск оставался простым и предсказуемым.
13. Как читатель, я хочу, чтобы переносы и повторные пробелы внутри одного текстового блока не мешали поиску фразы.
14. Как читатель, я хочу, чтобы поиск не склеивал разные абзацы или секции в одно совпадение.
15. Как читатель FB2, я хочу находить текст сносок в их расположении в конце книги.
16. Как читатель PDF, я хочу искать отдельно на каждой физической странице, чтобы результат однозначно соответствовал странице.
17. Как читатель, я хочу видеть все найденные совпадения подсвеченными, чтобы понимать контекст результатов.
18. Как читатель, я хочу видеть активное совпадение более контрастным, чтобы отличать текущий результат от остальных.
19. Как читатель, я хочу, чтобы найденный фрагмент автоматически прокручивался примерно в центр экрана.
20. Как читатель, я хочу переходить к следующему совпадению вперёд по книге.
21. Как читатель, я хочу переходить к предыдущему совпадению назад по книге.
22. Как читатель, я хочу, чтобы после последнего совпадения переход к следующему начинался с начала книги.
23. Как читатель, я хочу, чтобы перед первым совпадением переход к предыдущему начинался с конца книги.
24. Как читатель, я хочу, чтобы первый поиск начинался относительно текущей позиции чтения.
25. Как читатель, я хочу, чтобы после найденного результата дальнейшая навигация продолжалась относительно активного совпадения.
26. Как читатель, я хочу, чтобы ручная прокрутка не сбрасывала активное совпадение и последовательность навигации.

## Implementation Decisions

- Использовать один общий контроллер reader-а для состояния панелей, открытия/закрытия, `Ctrl/Cmd+F`, `Escape`, hover/touch-жестов, фокуса input и очистки выделений.
- FB2 и PDF подключают к общему контроллеру отдельные адаптеры поиска: извлечение текстовых областей, вычисление совпадений, создание подсветки, навигация и прокрутка к активному совпадению.
- Основной seam располагается на уровне reader-а; поведение панели не дублируется в формат-specific reader-ах.
- Верхняя и нижняя панели фиксированы поверх содержимого и всегда управляются как единое целое. Появление панелей не изменяет layout и не сдвигает позицию чтения.
- В нижней панели слева располагаются input, кнопки поиска и компактный счётчик; справа — формат-specific информация о позиции чтения.
- У search input нет визуального label, только placeholder `Поиск по книге`; для доступности используется невидимое имя поля.
- Поиск запускается только `Enter`, «Найти следующее» или «Найти предыдущее». Изменение input без действия поиска не меняет текущие результаты, выделения, счётчик или активное совпадение.
- Новый поиск использует актуальное значение input. Запрос очищается от начальных и конечных пробелов; пустой запрос не создаёт совпадений.
- Сопоставление регистронезависимое, по обычной подстроке, без регулярных выражений. Пробелы и переносы внутри одной поисковой области нормализуются.
- Совпадение не пересекает границы абзаца, секции или PDF-страницы. В FB2 текст сносок индексируется в расположении сносок в конце книги.
- До первого результата счётчик показывает серый `0/0`; при найденных результатах показывает `N/M` обычным цветом; при отсутствии результатов также показывает `0/0`.
- Первый поиск относительно текущей позиции идёт вперёд для «следующего» и назад для «предыдущего». После первого результата навигация идёт относительно активного совпадения и циклически переходит через границы книги.
- Все совпадения подсвечиваются, активное совпадение получает отдельное более контрастное выделение. При выборе результата reader прокручивается так, чтобы фрагмент находился примерно в центре viewport.
- Ручная прокрутка не сбрасывает активное совпадение. Закрытие панели, `Escape`, кнопка закрытия и клик/тап в `documentShell` снимают подсветку, но сохраняют текст input.
- Открытие поиска закрывает открытую боковую панель читалки или оглавление.
- Для touch-устройств одинарный тап по центру экрана переключает состояние единого overlay: скрытый overlay открывается, открытый закрывается.
- На узких экранах нижняя панель остаётся однострочной: элементы сжимаются, перенос строк не допускается.
- В FB2 справа показывается только существующий процент прочитанного, без ползунка позиции.
- В PDF справа показывается физический номер текущей страницы и общее число страниц. Текущая страница определяется страницей, пересекающей вертикальный центр viewport.
- PDF page input подтверждает переход по `Enter` или blur, ограничивает значение диапазоном `1..totalPages` и прокручивает к началу страницы с небольшим отступом под верхнюю панель. При фокусе input автоматическое обновление его значения временно приостанавливается.
- В PDF без встроенного текстового слоя поиск не использует OCR; результатом является `0/0`.
- Переход к найденному совпадению и переход к PDF-странице считаются сменой позиции чтения и проходят через существующее сохранение прогресса.
- Ожидается отсутствие изменений API, базы данных и серверной модели книги.

## Testing Decisions

- Тестировать внешнее поведение через Playwright, а не внутренние SolidJS-сигналы, DOM-структуру адаптера или детали расчёта диапазонов.
- Основной набор тестов разместить на общем seam reader-а: открытие/закрытие единого overlay, фокус и выделение input, `Ctrl/Cmd+F`, `Escape`, hover, touch tap, сохранение запроса и очистка подсветок.
- Отдельно покрыть FB2-адаптер: регистронезависимый поиск, нормализацию пробелов, границы блоков, поиск по сноскам в конце книги, циклическую навигацию и центрирование активного совпадения.
- Отдельно покрыть PDF-адаптер: поиск по страницам, отсутствие результатов для страницы без текстового слоя, обновление текущей страницы по центру viewport, переход по номеру страницы, clamping, Enter/blur и защиту focused input от автоматической перезаписи.
- Проверить, что переходы поиска и страницы вызывают обычное обновление прогресса и не нарушают восстановление позиции при следующем открытии.
- Добавить регрессионные проверки совместимости с уже существующими сценариями боковой панели, оглавления, настроек FB2, PDF outline и сохранения позиции при изменении ширины/настроек.
- Использовать существующий Playwright reader fixture и существующие e2e-сценарии reader-а как основу; component stories FB2/PDF использовать для ручной визуальной проверки компактной панели и разных ширин viewport.
- Проверять однострочность и доступность панели на узком viewport, включая touch-сценарий и отсутствие визуального label при наличии доступного имени input.

## Out of Scope

- OCR для сканированных PDF.
- Серверный полнотекстовый индекс, новые API endpoint-ы и изменения базы данных.
- Стандартный поиск браузера.
- Регулярные выражения, настройка чувствительности к регистру и дополнительные режимы поиска.
- Совпадения через границы абзацев, секций и PDF-страниц.
- Поиск по метаданным книги, названию файла, оглавлению или содержимому интерфейсных панелей.
- Ползунок позиции чтения для FB2.
- Поддержка напечатанных в PDF пользовательских номеров страниц вместо физических номеров страниц документа.
- Специальная логика перехода по `ArrowUp`/`ArrowDown` в PDF page input.

## Further Notes

- Перед реализацией уже зафиксированы архитектурные решения о клиентском поиске без OCR и едином верхнем/нижнем overlay reader-а.
- После реализации нужно актуализировать краткую документацию поведения приложения, если изменение будет включено в продукт.
- Спецификация не включает реализацию и создана как готовая задача для агента.
