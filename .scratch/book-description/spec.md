# Описание книги

Состояние: требования согласованы пользователем 2026-10-25, реализованы.

## Подтверждённые требования

- У книги появляется описание в дополнение к названию.
- Описание необязательно; его можно полностью удалить при редактировании. У существующих книг описание изначально пустое.
- Описание вводится вручную как обычный текст. Markdown и HTML не интерпретируются; извлечения аннотации из файла нет.
- При сохранении пробелы и переносы по краям обрезаются; значение из одних пробельных символов считается пустым. Внутренние пробелы, переносы и пустые строки сохраняются.
- Описание относится к персональной записи книги, аналогично названию; не изменяет исходный файл и метаданные книги другого пользователя.
- В формах добавления и редактирования поле описания находится сразу под полем названия.
- Вне этих форм описание пока не показывается.
- Поле многострочное; его начальная высота равна высоте однострочного поля ввода.
- Высота автоматически растёт и уменьшается по мере изменения содержимого, в том числе при вводе, удалении и вставке текста.
- Предзаполненное поле сразу получает высоту по содержимому.
- Строки считаются визуально, включая перенос текста по ширине. При изменении ширины поле пересчитывает высоту.
- Максимальная высота соответствует десяти строкам; при превышении появляется вертикальная прокрутка. Ручное растягивание отключено.
- Максимальная длина — 10 000 единиц UTF-16 при добавлении и редактировании, как в стандартном браузерном ограничении длины. Обычная буква, пробел или перенос строки занимают одну единицу, символ за пределами BMP (например, 🙂) — две. Frontend и сервер используют одинаковый подсчёт.
- Поле не позволяет ввести больше лимита. При вставке длинного текста вставляется только начальная часть, которая помещается в оставшийся лимит, без разрыва символа между единицами UTF-16. Учитывается замена выделенного текста.
- Сервер самостоятельно проверяет длину и отклоняет превышение без обрезания текста, в том числе при прямом API-запросе.
- Описание пока не участвует в поиске.
- У каждой книги в массовой загрузке собственное описание; при ошибке загрузки оно сохраняется в черновике для повтора.

## Выявленные ограничения

При загрузке сервер ограничивает все multipart-метаданные суммарно 10 КиБ
(`backend/internal/httpapi/book_upload.go`), а при редактировании принимает JSON
до 1 МиБ. Лимит multipart-метаданных потребуется увеличить с учётом максимального
описания в UTF-8 и остальных полей; предел описания должен одинаково работать
в обеих формах.

Сохраняемое поле требуется поддержать в PostgreSQL, SQLite и in-memory storage,
HTTP-контракте и frontend API. Поисковые условия остаются прежними. Описание
должно попадать в резервную копию вместе с остальными метаданными книги.

## Проверка поведения при реализации

- Пустое, заполненное и очищенное описание сохраняется при добавлении и редактировании; после повторного открытия формы значение совпадает с сохранённым.
- Пробельные края обрезаются, внутренние переносы сохраняются; разметка остаётся обычным текстом.
- Высота пустого поля совпадает с однострочным инпутом; начальное заполнение, вставка, удаление и изменение ширины корректно меняют высоту до десяти визуальных строк.
- После десяти визуальных строк появляется прокрутка, а после удаления лишних строк исчезает.
- Граничная длина принимается в обеих формах; превышение не вводится через UI и отклоняется прямым API-запросом.
- Подсчёт длины совпадает на frontend и сервере для кириллицы, переносов строк и эмодзи. Вставка при частично заполненном поле и замена выделения соблюдают лимит и сохраняют корректный текст.
- Совпадение только в описании не приводит к включению книги в результаты поиска.
- Описание одной книги не меняет описание другого черновика или книги другого пользователя; ошибка загрузки сохраняет введённое значение для повтора.
- Миграции сохраняют существующие книги с пустым описанием; резервное копирование и восстановление сохраняют описание.
