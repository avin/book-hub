# 12: Проверка полного сценария развёртывания

**What to build:** подтвердить готовность всей доработки в поддерживаемых способах запуска: сервер, CLI, миграции, реальные хранилища, кэш и перенос через backup/restore работают вместе, а эксплуатационные инструкции соответствуют итоговому поведению.

**Blocked by:** 10 — Backup/restore через удалённые хранилища; 11 — Совместная работа нескольких backend.

**Status:** resolved

**Основание:** [спецификация](../spec.md), все пользовательские истории и группы обязательных проверок; ADR-0008, ADR-0009, ADR-0010.

- [x] Поддерживаемые конфигурации запуска передают согласованные параметры серверу, admin CLI, backup CLI и мигратору. Проверены обе СУБД и оба варианта Compose; существующая локальная установка обновляется без ручного переноса.
- [x] Серверное и административные приложения собираются, миграции SQLite/PostgreSQL проходят, существующие гарантии сборки сохраняются.
- [x] Протокольные интеграционные проверки запускают реальные локальные FTP, explicit/implicit FTPS и S3-совместимый сервис и не требуют внешнего аккаунта пользователя. Выполнен общий цикл загрузки, чтения, скачивания и удаления с включённым кэшем для каждого типа хранения.
- [x] Подтверждён сценарий HDD/SSD: повторная выдача, запуск с сохранённым кэшем и периодическая проверка готовности не обращаются к оригиналам. Сохранены работа при отказах, строгие бюджеты и освобождение ресурсов.
- [x] Проверены сохраняемая очередь и конкурентные операции на обеих СУБД, а также два backend на PostgreSQL с независимыми кэшами. Применимые проверки выполнены с детектором гонок.
- [x] Полный цикл backup/restore выполнен в поддерживаемой среде с разными типами исходного и целевого хранилища. Подтверждены прежний комплект копии, старые поддерживаемые архивы и отсутствие зависимости восстановленной библиотеки от исходного сервиса.
- [x] HTTP-контракт и клиентские типы согласованы с итоговыми ошибками и выдачей. Существующие frontend-проверки подтверждают работу читалок и скачивания; при изменении обработки ошибки проверено соответствующее пользовательское поведение.
- [x] Описание текущего поведения и инструкции разработки/развёртывания актуализированы: один тип хранения на библиотеку, локальные изображения, оба FTPS, проверенные S3-сервисы, кэш по умолчанию выключен, отдельный рабочий лимит 1 ГиБ, восстановление в пустое место и ручной повтор после сбоя.
- [x] Итоговая проверка охватывает все обязательные группы спецификации. Для пропущенных проверок указаны конкретные причины; пропуск внешнего сервиса или PostgreSQL не считается прохождением соответствующего контракта.
- [x] Исправлены обнаруженные при совместной проверке несогласованности в пределах этой доработки. SFTP, импорт коллекций, отдельный перенос и другие исключённые возможности не добавлены.

**Проверка результата:** выполнить документированный сценарий новой установки, добавления и повторного открытия книги, временного отказа источника, удаления и полного переноса библиотеки через backup/restore; сверить результат с обязательными группами спецификации.

## Answer

Реализовано в `728caae`: добавлен cache-enabled HTTP-цикл всех пяти типов хранения и репозиторное
окружение настоящих FTP/FTPS/Garage/PostgreSQL с PowerShell/POSIX runner. Обе Compose-конфигурации
получили индивидуальные anonymous work/cache volumes backend с подготовленными ownership в image;
кэш по-прежнему выключен без явной пары параметров. Make направляет кэш локальной разработки в
`DEV_CACHE_DIR`, что закреплено red→green командным тестом. Исправлены окончания строк тикета 01
и смешанная кодировка ответа тикета 07.

Полный Linux `go test -p 2 -race ./...` с реальными PostgreSQL и всеми протоколами прошёл,
включая remote backup/restore, старые архивы, два backend и новый cache lifecycle. Все CLI собраны
для Linux с CGO=0. На обоих Compose-стеках в изолированных проектах прошли свежие миграции,
настоящие upload/download/range, cache после удаления оригинала и пересоздания backend,
остановленный CLI backup/validate/restore, HTTP восстановленной библиотеки и admin CLI.
OpenAPI повторно сгенерирован без diff, Go formatting и общий diff-check пройдены.

Полная матрица 16 групп, frontend evidence координатора и точные ограничения записаны в
[verification.md](../verification.md). Production multi-stage Docker build не запускался из-за
недостатка диска VM: Compose smoke использовал текущие Linux binaries в отдельном runtime image;
это не отмечено как прохождение полной Docker-сборки. Production данные и пользовательские volumes
не изменялись. POSIX helper проверен синтаксически; фактический запуск fixtures и Go snapshot runner
проверен PowerShell-скриптами с удалённым Docker context.
