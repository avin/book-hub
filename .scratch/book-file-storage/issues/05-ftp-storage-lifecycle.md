# 05: Полный цикл хранения на FTP

**What to build:** администратор подключает FTP как единственное хранилище оригиналов. Пользователь работает с книгами обычным способом, а отдельные изображения остаются рядом с backend.

**Blocked by:** 03 — Отдельная директория оригиналов и ограниченные рабочие файлы.

**Status:** ready-for-agent

**Основание:** [спецификация](../spec.md), истории 2, 12–16, 42, 43, 46; ADR-0008.

- [ ] Подключение и выделенная область FTP задаются серверной конфигурацией. Режим FTP выбирается явно; FTPS добавляется отдельной задачей.
- [ ] Загрузка сохраняет целый оригинал на FTP, а изображения локально. Успех возвращается только после сохранения оригинала и записи библиотеки.
- [ ] Чтение и скачивание получают полный оригинал через ограниченную рабочую директорию, проверяют размер и SHA-256 и выдают его через backend с сохранением прав доступа и HTTP-контракта.
- [ ] Дедупликация, квоты и удаление используют общие правила хранения. Протокольная реализация не дублирует согласованность библиотеки или механизм очереди.
- [ ] Приложение управляет только своей выделенной областью; импорт существующей сторонней коллекции и обход всего FTP-сервера не добавляются.
- [ ] Недоступный сервер, ошибка входа, прерванная запись или получение не объявляются успехом и не оставляют частичную книгу доступной для чтения. Временные файлы и резервы освобождаются.
- [ ] Настоящий адаптер проверен на изолированном локальном FTP-сервере через сценарии загрузки, чтения, скачивания, дедупликации и удаления, включая управляемый сбой передачи.
- [ ] Сервер и применимые CLI получают согласованную конфигурацию; поддерживаемые способы запуска и пользовательское поведение описаны в документации.

**Проверка результата:** выполнить HTTP-цикл книги с обложкой через локальный FTP, проверить один общий оригинал двух пользователей, его сохранение до последней ссылки и отсутствие успешной выдачи оборванного получения.
