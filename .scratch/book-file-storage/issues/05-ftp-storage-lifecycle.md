# 05: Полный цикл хранения на FTP

**What to build:** администратор подключает FTP как единственное хранилище оригиналов. Пользователь работает с книгами обычным способом, а отдельные изображения остаются рядом с backend.

**Blocked by:** 03 — Отдельная директория оригиналов и ограниченные рабочие файлы.

**Status:** resolved

**Основание:** [спецификация](../spec.md), истории 2, 12–16, 42, 43, 46; ADR-0008.

- [x] Подключение и выделенная область FTP задаются серверной конфигурацией. Режим FTP выбирается явно; FTPS добавляется отдельной задачей.
- [x] Загрузка сохраняет целый оригинал на FTP, а изображения локально. Успех возвращается только после сохранения оригинала и записи библиотеки.
- [x] Чтение и скачивание получают полный оригинал через ограниченную рабочую директорию, проверяют размер и SHA-256 и выдают его через backend с сохранением прав доступа и HTTP-контракта.
- [x] Дедупликация, квоты и удаление используют общие правила хранения. Протокольная реализация не дублирует согласованность библиотеки или механизм очереди.
- [x] Приложение управляет только своей выделенной областью; импорт существующей сторонней коллекции и обход всего FTP-сервера не добавляются.
- [x] Недоступный сервер, ошибка входа, прерванная запись или получение не объявляются успехом и не оставляют частичную книгу доступной для чтения. Временные файлы и резервы освобождаются.
- [x] Настоящий адаптер проверен на изолированном локальном FTP-сервере через сценарии загрузки, чтения, скачивания, дедупликации и удаления, включая управляемый сбой передачи.
- [x] Сервер и применимые CLI получают согласованную конфигурацию; поддерживаемые способы запуска и пользовательское поведение описаны в документации.

**Проверка результата:** выполнить HTTP-цикл книги с обложкой через локальный FTP, проверить один общий оригинал двух пользователей, его сохранение до последней ссылки и отсутствие успешной выдачи оборванного получения.


## Answer

Реализовано в `fdb61b4`: FTP-адаптер использует отдельные соединения на операцию, пассивную передачу, ограниченные ожидания и отмену через закрытие соединений. Оригинал публикуется через временное имя и переименование; чтение проходит общую полную проверку размера и SHA-256. Область ограничена выделенным FTP-каталогом; удаление уже отсутствующего файла подтверждается списком родителя. Обложки и миниатюры остаются локальными. `NewOriginals` отделяет создание источника от рабочих файлов; общий loader backup CLI завершается задачей 09.

Проверки: полный `go test ./...` на Windows и `go build ./cmd/...`; Linux `go test -p 2 -race ./internal/httpapi ./internal/storage/files ./internal/config` с `BOOK_HUB_TEST_FTP_ADDR=storage-fixtures:2121`. Реальный pyftpdlib-сервер: загрузка/чтение/скачивание, общий оригинал двух пользователей и последняя ссылка, обложки, ошибка входа без потери сессии, повреждённый файл без частичного успеха, освобождение рабочего места, отменённая передача с успешным повтором, границы области и Empty. Тестовый аккаунт `bookhub` / `bookhub-test-password`, каждый тест создаёт уникальный каталог в `/books`. PostgreSQL отдельно не повторялся в этой задаче; общие гарантии очереди покрыты задачей 02. Frontend/E2E не запускались — HTTP-контракт не изменён.
