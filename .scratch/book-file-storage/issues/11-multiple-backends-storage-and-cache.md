# 11: Совместная работа нескольких backend

**What to build:** два экземпляра backend на PostgreSQL используют общее хранилище оригиналов и независимые локальные кэши, сохраняя доступность книг и согласованность удаления при действиях через разные экземпляры.

**Blocked by:** 02 — Надёжное удаление оригиналов; 08 — Объединение одновременных получений.

**Status:** claimed

**Основание:** [спецификация](../spec.md), истории 15, 24, 26, 47–53; ADR-0007, ADR-0008, ADR-0009.

- [ ] Два настоящих HTTP-экземпляра на общей PostgreSQL-базе работают с общим хранилищем оригиналов и разными директориями кэша и рабочих файлов.
- [ ] Каждый экземпляр соблюдает собственные лимиты. Заполнение, вытеснение, перезапуск или неисправность одного кэша не повреждают другой.
- [ ] Одновременное получение объединяется внутри экземпляра; распределённое объединение или общая директория кэша не требуются. Наличие готовой копии позволяет конкретному экземпляру обслужить запрос без оригинала.
- [ ] Авторизация и принадлежность записи проверяются независимо от наличия копий в кэшах. Удалённая пользовательская запись не становится доступной через другой backend из-за сохранённой копии.
- [ ] Загрузка одинакового содержимого и удаление последней ссылки через разные экземпляры не уничтожают используемый оригинал. Проверка защищает фактическое удаление, а не только предварительное чтение ссылок.
- [ ] Сохраняемая очередь обрабатывается согласованно при нескольких экземплярах, сбоях и перезапусках; задача, созданная admin CLI, подчиняется тем же гарантиям.
- [ ] Локальные изображения сохраняют прежние требования доступности для обслуживающих их экземпляров; тестовая установка предоставляет их согласованно, не подменяя это общим кэшем.
- [ ] Конкурентные сценарии воспроизводятся управляемыми событиями на реальной PostgreSQL. SQLite сохраняет поддержку одного backend; обещание нескольких экземпляров на SQLite не добавляется.
- [ ] Инструкции многопроцессной установки явно различают общее хранилище оригиналов и отдельные локальные кэши, пути и бюджеты.

**Проверка результата:** прогреть разные кэши двух HTTP-экземпляров, независимо заполнить один из них и выполнить конкурентные загрузку и удаление общего файла через разные экземпляры; после перезапуска проверить сохранность доступных книг и обработку очереди.
