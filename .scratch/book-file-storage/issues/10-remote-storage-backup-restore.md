# 10: Backup/restore через удалённые хранилища

**What to build:** полный backup собирает оригиналы с FTP/FTPS/S3, а restore размещает их в выбранном локальном или удалённом хранилище. Администратор меняет тип хранения через прежние команды без отдельного инструмента переноса.

**Blocked by:** 04 — Полный цикл хранения в S3; 06 — Оба режима FTPS; 09 — Переносимый backup/restore для директорий.

**Status:** ready-for-agent

**Основание:** [спецификация](../spec.md), истории 54–61; ADR-0008, ADR-0010.

- [ ] Backup собирает все нужные оригиналы из активного FTP/FTPS/S3-хранилища, БД и локальные изображения. Выключенный или частично заполненный кэш не ограничивает полноту; кэш в копию не включается.
- [ ] Удалённое хранение не меняет привычный комплект и формат контейнеров копии. Недоступный или повреждённый необходимый оригинал не даёт успешно завершить полный backup.
- [ ] Restore размещает оригиналы в текущем настроенном хранилище, изображения локально и пересчитывает ссылки БД. Исходный сервис после создания корректной копии не нужен.
- [ ] До изменения данных проверяется пустота именно выделенной директории или префикса назначения. Чужие объекты вне этой области не затрагиваются; очистка всего FTP-сервера или бакета исключена.
- [ ] Старые поддерживаемые архивы можно восстановить в новое удалённое хранилище при той же СУБД. Смена СУБД и отдельная команда миграции оригиналов не добавляются.
- [ ] Сохраняются контроль размера и SHA-256, автоматический запуск после успешного backup и остановленное приложение после неудачного restore. Прерывание не выдаётся за успешное восстановление; повтор выполняется после ручной очистки выделенного назначения.
- [ ] Интеграционная матрица включает локальное → удалённое, удалённое → локальное и удалённое → другой поддерживаемый тип, покрывает FTP, оба режима FTPS и S3 как источник и назначение. Используются локальные тестовые серверы и реальные адаптеры.
- [ ] После каждого успешного восстановления проверяются файлы, обложки, метаданные и права через HTTP при недоступном исходном сервисе. Сценарий проверяется для SQLite и PostgreSQL в пределах одной СУБД.
- [ ] Документация описывает backup → перенастройка → restore, пустое назначение, отдельную потребность в месте и сохранённый автоматический запуск после backup с принятым риском новых записей в промежутке.

**Проверка результата:** сделать полный backup удалённой библиотеки, отключить исходный сервис и восстановить копию в пустое хранилище другого типа; проверить доступность книг и изображений через приложение.
