# 09: Переносимый backup/restore для директорий

**What to build:** полный backup локальной библиотеки можно восстановить в другую директорию оригиналов при той же СУБД. Сохраняются привычный комплект копии и поддержка старых архивов; пути пересчитываются, а непустое назначение отклоняется заранее.

**Blocked by:** 03 — Отдельная директория оригиналов и ограниченные рабочие файлы.

**Status:** resolved

**Основание:** [спецификация](../spec.md), истории 54–61; ADR-0010, ADR-0007.

- [x] Полная копия включает согласованную БД, все необходимые оригиналы и локальные изображения, даже если они размещены в разных директориях. Кэш не является источником полноты и в архив не включается.
- [x] Сохраняются manifest.json, database.sql либо database.sqlite и storage.tar.gz. Новая версия формата контейнера не вводится только ради отделения оригиналов; штатная версия схемы БД учитывается отдельно.
- [x] При backup и restore проверяются размер и SHA-256 книг. Неполный или повреждённый набор не объявляется успешной полной копией.
- [x] Restore в другую директорию пересчитывает ссылки на оригиналы и локальные изображения. После восстановления книги и обложки доступны через HTTP без исходного расположения.
- [x] Поддерживаются прежние поддерживаемые копии обеих СУБД, включая PostgreSQL без manifest и прежние абсолютные или относительные пути. Совместимость подтверждается реальными прежними структурами архивов, а не предположением, что архив всегда содержал только оригиналы и обложки.
- [x] Пустота выделенного назначения оригиналов и применимые ограничения копии проверяются до изменения БД и назначения. Другая СУБД, неподдерживаемый формат, некорректный архив и непустое назначение отклоняются без изменений при предварительной проверке.
- [x] Сохраняются SQLite-снимок с учётом WAL, действующие требования исключения параллельной записи и автоматический запуск приложения после успешного backup/restore. Новый режим, оставляющий приложение остановленным после backup, не добавляется.
- [x] При ошибке или прерывании restore после начала изменений приложение остаётся остановленным и сообщается причина. Автоматического продолжения или отката нет; описан повтор из того же архива после очистки выделенного назначения.
- [x] Полный цикл и ошибки проверены на реальных SQLite и PostgreSQL через существующие публичные операции backup/restore и применимые командные сценарии. Ограничение рабочего места сервера не подменяет отдельную потребность backup в дисковом пространстве.

**Проверка результата:** создать копию библиотеки с оригиналами и изображениями в разных местах, сделать исходное расположение недоступным, восстановить в пустую другую директорию и проверить данные через HTTP; отдельно восстановить старую поддерживаемую копию.

## Answer

Реализовано в `b6874af`; совместимость с FTP-конфигурацией сохранена при слиянии `2f42b64`.
Backup собирает используемые оригиналы и локальные изображения, проверяет размер и SHA-256 и записывает manifest последним. Кэш, рабочие файлы и оригиналы без владельцев не требуются для полноты копии. Restore проверяет архив и пустоту назначения до изменений, переносит оригиналы и изображения, пересчитывает ссылки, обновляет старую схему штатными миграциями и убирает старые задачи удаления без владельцев.

PostgreSQL inventory читается из поддерживаемого plain `pg_dump COPY` без нового требования права `CREATE DATABASE`; произвольный SQL этим читателем не интерпретируется. Прежние архивы с `./`, временными и служебными записями поддерживаются; восстанавливаются необходимые книги и локальные изображения. `config.LoadFileStorage` и `files.NewOriginals` дают CLI общую конфигурацию без HTTP-секрета и инициализации кэша/рабочих файлов другого процесса.

Проверки: полный `go test ./...` с реальной PostgreSQL и `go build ./cmd/...` на Windows; Linux `go test -p 2 -race ./internal/backup ./cmd/book-hub-backup ./internal/config` с PostgreSQL 17 и matching pg tools. Проверены SQLite WAL, обе СУБД с недоступным исходным расположением и доступом к книге/обложкам через HTTP, прежние схемы и пути, старый tar и PostgreSQL без manifest, повреждение и отсутствие обязательных файлов, непустое назначение, пересечение путей через symlink, исключение незавершённого удаления, а также пять командных сценариев stop/start и отказов Make. Frontend/E2E здесь не запускались: интерфейс не менялся. Удалённые матрицы восстановления относятся к задаче 10.
