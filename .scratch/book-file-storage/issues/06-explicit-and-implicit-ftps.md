# 06: Оба режима FTPS

**What to build:** администратор может выбрать explicit или implicit FTPS для полного цикла работы с оригиналами, с проверкой сертификата и поддержкой собственного доверенного CA.

**Blocked by:** 05 — Полный цикл хранения на FTP.

**Status:** resolved

**Основание:** [спецификация](../spec.md), истории 3–6; ADR-0008.

- [x] FTP, explicit FTPS и implicit FTPS различаются явной конфигурацией; режим не выбирается случайным перебором или автоматическим понижением защиты.
- [x] Explicit FTPS включает TLS после подключения, implicit FTPS устанавливает TLS сразу. В обоих режимах защищены предусмотренные протоколом передача учётных данных и передача файлов.
- [x] Проверяются сертификат и имя сервера. Можно настроить собственный доверенный CA без отключения проверки сертификатов.
- [x] Ошибка TLS или недоверенный сертификат не приводят к попытке незашифрованного FTP и не подтверждают сохранение или выдачу книги.
- [x] Оба режима поддерживают загрузку, чтение, скачивание и удаление через общий механизм оригиналов с прежними квотами, дедупликацией и локальными изображениями.
- [x] Локальные FTPS-проверки используют настоящие соединения и покрывают оба режима, доверенный сертификат, недоверенный сертификат, собственный CA и несовпадение имени сервера. Проверено отсутствие перехода на FTP.
- [x] Конфигурация сервера и CLI и инструкции подключения включают оба режима и настройку доверенного CA. SFTP в задачу не входит.

**Проверка результата:** выполнить полный цикл книги отдельно через explicit и implicit FTPS; заменить доверие или имя сертификата и убедиться в отказе операции без обращения по незашифрованному FTP.

## Answer

Реализовано в `e4aa2d2`, интеграционная ветка с S3 и кэшем включена в `8e33eff`. Режимы задаются явно через `BOOK_HUB_BOOK_STORAGE=ftp|ftps-explicit|ftps-implicit`; `BOOK_HUB_FTP_CA_FILE` добавляет доверенный CA, сохраняя проверку сертификата и имени сервера. Управляющий и передающий каналы используют TLS; автоматического перехода на FTP нет. Общий загрузочный цикл, дедупликация, очередь удаления и локальные изображения сохранены. Сервер и CLI используют общий загрузчик конфигурации.

При проверке большой передачи найдено и исправлено преждевременное закрытие TLS-сокета: после отправки `close_notify` адаптер дочитывает завершение TLS перед закрытием TCP. Ожидание ограничено тайм-аутом и отменой контекста. Проверяется полное многомегабайтное содержимое после загрузки, отмена чтения и успешный повтор в обоих режимах.

Финальные проверки после слияния: `go test -race ./internal/config ./internal/storage/files ./internal/httpapi` и `go build ./cmd/...` прошли на Windows. В Linux прошёл `go test -p 2 -race -count=1 -run TestFTP ./internal/storage/files ./internal/httpapi` с настоящими FTP, explicit FTPS и implicit FTPS: полный HTTP-цикл, локальные обложки, дедупликация, удаление последней ссылки, повреждение и повтор, неверный пароль без потери сессии, доверие CA, недоверенный сертификат, неверное имя и наблюдаемое отсутствие повторного подключения с открытыми учётными данными. Первую попытку остановило переполнение отдельного кэша компиляции; после очистки только старых файлов этого тестового кэша повтор прошёл. Frontend и E2E для этой серверной задачи отдельно не повторялись.

Переменные интеграционных проверок: `BOOK_HUB_TEST_FTP_ADDR`, `BOOK_HUB_TEST_FTPS_EXPLICIT_ADDR`, `BOOK_HUB_TEST_FTPS_IMPLICIT_ADDR`, `BOOK_HUB_TEST_FTPS_CA_FILE`. В подготовленном окружении адреса — `storage-fixtures:2121`, `storage-fixtures:2122`, `storage-fixtures:2990`, CA — `/fixtures/server.pem`. Подробности воспроизводимого запуска — в `DEV.md`; каждая проверка использует отдельный префикс.
