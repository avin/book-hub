# 07: Постоянный локальный кэш с LRU

**What to build:** пользователь повторно читает и скачивает книгу из ограниченного локального кэша без обращения к оригиналу, в том числе на спящем HDD. Кэш сохраняется между перезапусками и безопасно обходится, если использовать его нельзя.

**Blocked by:** 03 — Отдельная директория оригиналов и ограниченные рабочие файлы.

**Status:** resolved

**Основание:** [спецификация](../spec.md), истории 17–29, 32–34, 38–41, 44, 45; ADR-0008, ADR-0009.

- [x] Кэш по умолчанию выключен. Для включения явно задаются локальный путь и положительный максимальный размер; некорректные значения обнаруживаются при запуске.
- [x] Один механизм кэширования применяется к директории и подключаемым удалённым источникам, к чтению и скачиванию. Готовая копия одинакового исходного файла общая для пользователей одного backend; право доступа проверяется перед каждой выдачей.
- [x] При попадании отсутствуют обращения к оригиналу, включая чтение, stat и HEAD. Это проверяется управляемым источником, который фиксирует или запрещает любое обращение.
- [x] При промахе целый файл получен и проверен до публикации готовой копии и начала выдачи. Уже проверенная копия заново целиком на каждом запросе не хешируется.
- [x] Лимит учитывает готовые и скачиваемые в кэш файлы; место под полный размер резервируется заранее. Совокупный бюджет соблюдается при параллельных получениях разных книг.
- [x] Чтение и скачивание обновляют LRU. Текущие выдачи защищены от вытеснения; при невозможности освободить место лимит не превышается.
- [x] Завершённые копии переживают перезапуск, незавершённые убираются. Проверка и использование сохранённого кэша при запуске не требуют доступности оригиналов.
- [x] Слишком большой файл, отключённый, заполненный или неисправный кэш используют общий обход: локальный оригинал напрямую, удалённый через отдельно ограниченную рабочую директорию. Ошибка кэша фиксируется в логе и не блокирует доступный обход или запуск backend.
- [x] После успешной загрузки уже принятый файл по возможности остаётся в кэше без обратного скачивания. Ошибка кэша или обложки не отменяет успешное сохранение оригинала.
- [x] При недоступных оригиналах кэшированные книги доступны после проверки прав. Промах возвращает временную ошибку без потери сессии; readiness не проверяет оригиналы и не блокируется только из-за необязательного кэша при рабочем обходе.
- [x] HTTP-проверки покрывают LRU, лимит, активную выдачу, перезапуск, целостность, права разных пользователей и работу с отключённым источником. Настройки и сценарий HDD/SSD описаны в документации.

**Граница:** объединение нескольких незавершённых запросов одной книги и правила отмены общего получения завершаются в задаче 08; строгий бюджет и отсутствие дубликатов готовых копий обязательны уже здесь.

**Проверка результата:** получить книгу в кэш, отключить оригиналы, перезапустить backend и прочитать её снова; затем проверить вытеснение другой книги и обход для файла, который не помещается.


## Answer

Реализовано в `888468d`, с интеграцией FTP и переносимого backup в `d1bbc50`: кэш целых файлов в `files` использует отдельный строгий бюджет готовых и получаемых файлов, LRU с сохранением давности между перезапусками и защищённые выдачи. При запуске проверяет только локальные копии, удаляет частичные и повреждённые файлы. `Store.OpenBook` сначала использует готовую копию без обращения к оригиналам; `Store.SeedBook` сохраняет уже принятый файл после успешной загрузки. Ошибки кэша записываются в лог и допускают прямой локальный либо ограниченный рабочий обход. Admin CLI создаёт только источник оригиналов и не инициализирует кэш backend.

Конфигурация: пара `BOOK_HUB_CACHE_DIR` и положительный `BOOK_HUB_CACHE_MAX_BYTES`, по умолчанию выключено. Каталог не пересекается с изображениями, рабочими файлами и локальными оригиналами. HTTP-контракт не изменён.

Проверки: полный Go-набор и сборка приложений на Windows; после объединения с задачами 05/09 — HTTP/files/config/admin с `-race` и сборка CLI. HTTP-тесты подтверждают права владельцев и отзыв доступа, одну копию для одинаковых файлов, заполнение из принятой загрузки, отсутствие обращений к оригиналам при попадании/перезапуске/readiness, LRU чтения и скачивания с перезапуском, защиту активной HTTP-выдачи, общий бюджет готовых и получаемых файлов, отмену и освобождение резервов, целостность и повтор, очистку частичных/повреждённых копий, отключённый/неисправный/малый кэш, локальный прямой обход и недоступный HDD. Настоящий ENOSPC проверен в Linux с `-race`: `TestBookCacheDiskFullWriteFallsBackToBoundedWorkspace` на выделенном tmpfs меньше 128 КиБ; ошибка записи seed и получения не мешает успешному HTTP-ответу через ограниченную рабочую директорию, частичные файлы удалены. Отдельно проверен сбой публикации готовой копии с успешным обходом. Проверки PostgreSQL и протоколов не повторялись: их контракт не менялся; E2E остаются итоговой задаче 12.

Объединение незавершённых запросов и отмена общего получения остаются задачей 08. Сейчас конкурентный промах того же хеша допускает обход, не создавая второй готовой копии и не превышая бюджет кэша.
