# Итоговое ревью book-file-storage

База сравнения: `ee89b7c`; проверена интеграционная ветка после задач 01–12.

## Standards

Нарушений документированных стандартов и требующих исправления эвристических замечаний не найдено.
Дублирование SQL PostgreSQL и SQLite соответствует существующему разделению адаптеров.

## Spec

Найдены и исправлены два замечания:

- **P1: неполная копия при симлинке в пути каталога изображений.** `archiveLibrary` теперь разрешает
  корневой симлинк перед обходом. Симлинки внутри дерева по-прежнему отклоняются.
  `TestPortableBackupRestoresImagesFromSymlinkedRoot` проверяет создание, валидацию и восстановление
  копии с чтением книги, обложки и миниатюры через HTTP после удаления источника.
  `TestPortableBackupRejectsLinksInsideImages` сохраняет запрет внутренних ссылок и публикации неполной копии.
- **P2: голодание очереди за первыми 100 неудачными удалениями.** PostgreSQL и SQLite проходят
  очередь пакетами с продвижением по ключу, включая неудачные задачи. Верхняя граница прохода
  фиксируется при его начале. Блокировки оригиналов и транзакционная проверка владельцев сохранены.
  Общий контракт `failed deletions do not block other originals or their later retries` проверяет
  удаление здорового 101-го оригинала, сохранение остальных задач после повторного открытия БД
  и завершение повторов после восстановления источника.

## Проверка исправлений

Оба регрессионных сценария сначала воспроизвели ошибки, затем прошли после исправлений.
Пройден Linux-набор с настоящими PostgreSQL и SQLite:

```sh
go test -p 2 -race ./internal/backup ./internal/storage/db ./internal/storage/sqlite ./internal/storage/memory
```

Он включает новые сценарии, прежние контракты хранения, локальные и старые резервные копии.
Сборка всех CLI через `go build ./cmd/...` также пройдена. Протокольная матрица и frontend
после этих правок не повторялись: адаптеры протоколов и публичный HTTP-контракт не изменены.

Итого: исходных замечаний Standards — 0, Spec — 2; оба замечания Spec исправлены и покрыты проверками.
