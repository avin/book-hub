# Глобальная блокировка страницы

Во время операций, которые нельзя безопасно прервать действиями пользователя, приложение использует единую глобальную блокировку страницы. Блокировка предоставляется общим UI-компонентом и хуком, чтобы разные страницы могли включать её одинаково; для batch-загрузки книг она действует от начала первой отправки до завершения всех попыток. Это сохраняет целостность операции и не привязывает механизм к странице загрузки.

API локера намеренно простой: `lockPage()`, `unlockPage()` и `isPageLocked`; одновременно предполагается только одна блокирующая операция.

Локер отображается как прозрачный полноэкранный слой с захватом фокуса и без отмены операции. Пользовательский индикатор прогресса остаётся ответственностью запускающей страницы.

## Considered Options

- Локальная блокировка только внутри страницы загрузки — отклонена, потому что такой механизм потребуется и другим операциям.
- Блокировать только отдельные кнопки — отклонено, потому что пользователь всё ещё может сменить маршрут или изменить состояние соседних компонентов.

## Consequences

- Любая страница может использовать единый механизм блокировки.
- Владелец операции обязан гарантировать снятие блокировки после завершения или ошибки.
- При ошибке части batch-операции блокировка снимается только после попытки обработки всего batch.
- Локер не перехватывает браузерную навигацию; при принудительном уходе операция освобождает локальные ресурсы и игнорирует поздние обновления состояния.
