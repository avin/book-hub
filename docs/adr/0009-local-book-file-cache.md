# Локальный кэш целых файлов книг

Решение согласовано; ожидает реализации.

При отсутствии книги в кэше backend сначала получает исходный файл целиком и проверяет его, затем начинает выдачу. Дополнительное ожидание первого открытия принято ради единого поведения директории, FTP, FTPS и S3 и сохранения частичных HTTP-запросов при выдаче локального файла.

Кэш использует LRU: чтение и скачивание обновляют давность использования, а файлы текущих выдач защищены от вытеснения. Завершённые файлы сохраняются между перезапусками, незавершённые загрузки убираются; проверка кэша при запуске не требует обращения к оригиналам.

Для одинакового исходного файла используется одна кэшированная копия на экземпляр backend независимо от числа пользователей. Доступ каждый раз проверяется по библиотеке пользователя; наличие файла в кэше само по себе не даёт права получить его.

После успешной загрузки оригинала backend сохраняет уже принятый файл в кэше, если кэш включён и файл помещается. Ошибка кэширования не отменяет успешного сохранения книги в основном хранилище.

Лимит размера кэша строгий и учитывает готовые и скачиваемые в кэш файлы. Место под полный размер файла резервируется заранее. Если размер книги превышает лимит или нужное место нельзя освободить из-за активных выдач, лимит не превышается.

Если файл не помещается, кэш отключён или недоступен, оригинал из директории выдаётся напрямую, а оригинал из FTP/FTPS/S3 сначала загружается в отдельную локальную рабочую директорию. Временный файл удаляется после завершения выдач. Эти файлы требуют места сверх лимита кэша; их общий объём ограничивается отдельно. Ошибка кэша записывается в лог и не блокирует этот обходной путь; если получение или временное сохранение оригинала невозможно, запрос завершается временной ошибкой.

Одновременные запросы одного исходного файла используют одно скачивание на экземпляр backend и ждут общий результат. Уход одного клиента не отменяет скачивание для остальных; при отсутствии ожидающих клиентов незавершённая операция отменяется.

При получении оригинала проверяются размер и SHA-256 из БД. Повреждённый файл не выдаётся и не принимается в кэш. Проверенная кэшированная копия не хешируется целиком заново при каждом запросе.

Кэш по умолчанию выключен. Для включения администратор явно задаёт путь и максимальный размер; некорректные значения конфигурации обнаруживаются при запуске. Недоступность корректно настроенной директории кэша обрабатывается как ошибка кэша с обходным получением оригинала.

Для временных файлов загрузки новых книг и получения оригиналов используется отдельная локальная рабочая директория с настраиваемым общим лимитом; по умолчанию — 1 ГиБ на экземпляр backend. Этот лимит действует отдельно от лимита кэша. При нехватке места по лимиту новая операция завершается временной ошибкой, текущие выдачи продолжаются. Дисковое место для backup учитывается отдельно.
