# Семантические CSS-токены для темизации

## Status

Accepted

## Context

Цвета в проекте хранились как compile-time SCSS-переменные (`$color-ink-950`, `$color-paper-0` и т.д. в `src/styles/_variables.scss`) и инлайнились в каждый `.module.scss`. Темы не поддерживались вовсе. Появилась задача: несколько светлых и несколько тёмных тем, выбор по умолчанию по `prefers-color-scheme`, переключение в runtime.

## Decision

Перевести цвета на **семантические CSS custom properties** (~45 токенов, гранулярно) и переопределять их под каждый `[data-theme="..."]`. Существующий код (`background: $color-paper-50`) не переписывается построчно — `_variables.scss` переопределяет SCSS-переменные как ссылки на `var(--token)`, однако каждому использованию цвета назначается осмысленный семантический токен (а не 1:1 по старым именам), чтобы тёмные темы были объёмными.

Токены сгруппированы: surfaces (7), text (7), accent (6), border (4), danger/success/warning (по 4), shadow (3), focus/favorite. Каждая тема задаёт значения для всех.

Применение темы — через атрибут `data-theme` на `<html>`. Значение хранится в `browserPreferences` (localStorage), как и остальные UI-настройки (язык, reader-настройки, режим отображения списка). Для избежания FOUC инлайн-скрипт в `index.html` ставит атрибут до первого пэйнта. Дефолт при первом визите — по `prefers-color-scheme: light/dark`. Набор тем: 3 светлых (Warm Clay, Cool Slate, Sage Green) + 3 тёмных (Warm Ink, Charcoal Green, Neutral Graphite).

Зона ридера (FB2/PDF) изолирована: собственные цвета пользователя (`Fb2ReaderSettings.backgroundColor` и т.д.) не подчиняются теме приложения.

## Considered Options

- **Грубые ~10 токенов** (`--surface`, `--text`, `--accent`). Отвергнуто: тёмные темы получаются «плоскими», бордеры и приподнятые поверхности пропадают.
- **Покомпонентные ~40+ токенов** (`--button-primary-bg`, `--bookcard-border`). Отвергнуто как оверкилл: дублирование между темами, неуправляемый дифф.
- **Compile-time темы через отдельные сборки.** Отвергнуто: не даёт runtime-переключения.

## Consequences

- Откат темизации назад дорогой: после миграции каждое цветовое использование завязано на токен. Это и есть причина фиксации решения.
- Добавление новой темы = ещё один блок значений токенов в `app.scss` (или где определены темы), без правок компонентов.
- Захардкоженных hex в компонентах быть не должно — всё через токены. Это уже соблюдается, нужно лишь поддерживать.
