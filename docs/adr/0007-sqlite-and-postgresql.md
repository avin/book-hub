# SQLite и PostgreSQL как варианты базы данных

Администратор выбирает SQLite или PostgreSQL при настройке Book Hub; обе СУБД должны поддерживать все текущие функции приложения, включая нескольких пользователей, права доступа и сохранение прогресса чтения. SQLite поддерживается для одного экземпляра backend с базой на локальном диске сервера и одновременной работой нескольких пользователей и устройств; для нескольких экземпляров backend выбирается PostgreSQL. Такая граница позволяет предложить SQLite как самостоятельный вариант установки, сохранив PostgreSQL для другого сценария эксплуатации; перенос данных между СУБД выделен в отдельный этап.

СУБД определяется по схеме обязательной `BOOK_HUB_DATABASE_URL`, сохраняя совместимость существующих PostgreSQL URL. SQLite реализует существующий `storage.Store` отдельно от PostgreSQL, с общими проверками поведения и сборкой без CGO. Для различающихся SQL-диалектов поддерживаются отдельные наборы миграций с сохранением истории PostgreSQL; обе СУБД обновляются отдельным мигратором перед запуском сервера.

Для SQLite используется pure-Go драйвер `modernc.org/sqlite` с SQLite-адаптером существующего `golang-migrate`. База размещается по абсолютному пути в отдельном постоянном volume Docker. Временная блокировка БД обрабатывается ограниченным ожиданием и ответом `503 service_unavailable`, включая авторизацию, без повторения изменяющего HTTP-запроса целиком.

Паритет означает одинаковые функции и буквальный регистронезависимый поиск, но допускает различия алфавитного порядка отдельных символов между СУБД: это сохраняет существующую PostgreSQL-сортировку без введения общего порядка для всех установок. При равных основных ключах порядок закрепляется через ID книги.
