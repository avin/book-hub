# Отдельное хранилище исходных файлов книг

Решение согласовано; ожидает реализации.

Для всей библиотеки выбирается одно активное хранилище исходных файлов книг: директория, FTP, FTPS или S3. Book Hub управляет сохранением и удалением файлов; обнаружение и импорт произвольной существующей коллекции в эту доработку не входят. Такой выбор сохраняет единый жизненный цикл файлов и не требует распределять книги между несколькими хранилищами.

Отдельные обложки и прочие отдельно сохраняемые изображения приложения остаются на сервере backend. Встроенные иллюстрации остаются внутри исходного файла книги: его содержимое не преобразуется ради смены хранилища.

SFTP в первый этап не входит; его добавление в будущем допускается.

Тип хранилища, параметры подключения и кэша задаются переменными окружения и применяются после перезапуска сервера. S3 включает Amazon S3 и сервисы с совместимым API; endpoint, регион, бакет, префикс и учётные данные настраиваются, проверенные сервисы перечисляются в документации.

Поддерживаются FTP, explicit FTPS и implicit FTPS с явным выбором режима. FTPS проверяет сертификат сервера и допускает настройку собственного доверенного CA; автоматический переход на незашифрованный FTP при ошибке TLS исключён.

Чтение и скачивание используют один механизм получения файлов через backend с проверкой доступа. Браузер напрямую к хранилищу не обращается. Необязательный локальный кэш поддерживается для всех вариантов хранилища, включая директорию: например, оригиналы лежат на медленном HDD, а кэш — на SSD. Попадание в кэш не требует обращения к хранилищу оригиналов.

Правила заполнения, выдачи и вытеснения определены в [ADR-0009](0009-local-book-file-cache.md).

С PostgreSQL сохраняется поддержка нескольких экземпляров backend с общим хранилищем книг. Каждый экземпляр использует собственную директорию кэша и свой лимит; совместное использование директории кэша несколькими процессами не поддерживается.

Исходные файлы неизменяемы, выделенной областью хранилища управляет только Book Hub. Автоматическая синхронизация ручных изменений и удалений в хранилище не входит в доработку.

Настройка хранилища рассчитана на выбор при первоначальной установке. Отдельного механизма переноса между хранилищами не будет: для смены администратор делает полный backup, перенастраивает сервер и восстанавливает backup в новое хранилище. Требования к переносимости копий определены в [ADR-0010](0010-storage-independent-backups.md).

После удаления последней ссылки книга сразу исчезает из библиотеки, а удаление исходного файла ставится в сохраняемую очередь и повторяется фоном при сбоях. Перед повторным удалением проверяется, не появились ли новые ссылки на файл; согласованность этой проверки с загрузкой должна сохраняться и между экземплярами backend.

Недоступность хранилища оригиналов не препятствует запуску backend и выдаче доступных кэшированных файлов. Запрос отсутствующего в кэше файла завершается временной ошибкой, а новая загрузка успешна только после сохранения оригинала в основном хранилище. Периодическая проверка готовности не обращается к хранилищу оригиналов, чтобы не будить HDD; проверки БД, локальных изображений и рабочих директорий выполняются отдельно.
