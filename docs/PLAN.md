# Book Hub: техническое задание и общий план

## Цель

Book Hub - приватное веб-приложение для хранения и чтения книг пользователя.
Пользователь регистрируется на сайте, но вход возможен только после активации
аккаунта администратором через серверный CLI. После входа пользователь может
загружать книги, управлять метаданными, читать книги и продолжать чтение с любого
устройства за счет сохраненного прогресса на сервере.

## Состав системы

- Backend: Go HTTP API.
- Admin CLI: отдельный Go CLI-инструмент для серверного администрирования.
- Frontend: статическое приложение на SolidJS.
- Database: PostgreSQL.
- File storage: локальная директория на сервере.
- Deployment: Docker Compose.
- API contract: сначала OpenAPI-спецификация, затем реализация backend по ней.

## Основные пользовательские сценарии

- Регистрация нового пользователя.
- Ожидание активации аккаунта администратором.
- Вход активированного пользователя.
- Загрузка одной книги.
- Просмотр списка своих книг.
- Фильтрация и отображение книг по пользовательским данным.
- Редактирование названия, тегов и признака избранного.
- Открытие книги для чтения.
- Сохранение прогресса чтения.
- Продолжение чтения с другого устройства.
- Сброс прогресса чтения.
- Полное удаление книги из библиотеки пользователя.
- Удаление физического файла только когда он больше не используется ни одним
  пользователем.
- Сохранение frontend-настроек отображения как opaque JSON без серверного
  парсинга.

## Административные сценарии

Администрирование доступно только через CLI на сервере. У пользователей нет ролей,
админского входа на сайте и web-admin интерфейса.

- Создание пользователя.
- Активация пользователя.
- Деактивация пользователя.
- Удаление пользователя.
- Смена пароля пользователя.
- Изменение квоты пользователя.
- Просмотр занятого объема пользователем.
- Просмотр списка пользователей.

CLI не требует пароля, так как предполагается запуск только человеком с доступом к
серверной консоли.

## Ограничения и правила

- По умолчанию квота пользователя: 2 GB.
- Квоту нельзя уменьшить ниже уже занятого объема пользователя.
- В квоту пользователя входит полный размер каждой его книги, даже если физический
  файл дедуплицирован и используется несколькими пользователями.
- Физические файлы хранятся по hash-based имени.
- Одинаковые книги физически хранятся один раз.
- При удалении книги из библиотеки пользователя файл удаляется с диска только если
  больше нет ссылок на него от других пользователей.
- Первые поддерживаемые форматы: FB2 и PDF.
- Для PDF viewer во frontend позже используется pdf.js.
- Для FB2 viewer позже используется собственное решение.
- Детальная реализация viewer сейчас вне scope.

## Frontend scope для первой итерации

В первой реализации frontend должен быть номинальным:

- SolidJS-проект.
- Статическая страница `index.html`.
- Текст на странице: `в разработке`.
- Без реализации авторизации, списка книг, загрузки, чтения и настроек.

## Backend scope для первой итерации

- OpenAPI-спецификация всех API endpoints.
- HTTP API на Go по OpenAPI-контракту.
- PostgreSQL-интеграция.
- Миграционные файлы с поддержкой upgrade/downgrade.
- Локальное файловое хранилище книг.
- Дедупликация файлов по hash.
- Проверка пользовательской квоты.
- Самостоятельная смена пароля пользователем после входа.
- Cookie-session auth.
- Admin CLI.
- Docker Compose для запуска backend, frontend static server и PostgreSQL.
- README с инструкцией установки и настройки.

## Не входит в первую итерацию

- Полноценный frontend UI.
- Реализация PDF reader.
- Реализация FB2 reader.
- Извлечение и нормализация содержимого книг.
- Web admin panel.
- Пользовательские роли.
- Email, email-подтверждение и любые email-уведомления.
- Восстановление пароля пользователем.
- Внешнее объектное хранилище.
- Платежи, тарифы и self-service изменение квоты.

## Не планируется вообще

- Поиск по тексту книг.

## Ключевые проектные решения

- Source of truth для API - OpenAPI-файл.
- Backend и CLI используют одну доменную модель и один слой доступа к БД.
- Auth модель: cookie-session с HttpOnly, Secure, SameSite=Lax cookie.
- Максимальный размер одного upload-запроса: 300 MB.
- Backend не интерпретирует frontend-настройки отображения, а хранит их как JSON.
- Прогресс чтения хранится только как `progress_percent` и `updated_at`.
- Файлы книг и пользовательские записи книг разделены: один физический файл может
  иметь много пользовательских записей.
- Удаление пользователя удаляет его сессии, библиотеку, прогресс, настройки и
  физические файлы его книг, если эти файлы больше не используются другими
  пользователями.
- Удаление пользовательской книги должно быть транзакционно согласовано с
  изменением ссылок на физический файл; физическое удаление файла выполняется
  после успешной фиксации изменений в БД.
