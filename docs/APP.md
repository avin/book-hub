# Book Hub

Book Hub - приватное self-hosted веб-приложение для хранения личной библиотеки и чтения книг в браузере.

## Назначение

Приложение решает три задачи:

- хранит пользовательские PDF и FB2 книги;
- дает веб-интерфейс для загрузки, каталогизации и чтения;
- синхронизирует метаданные, настройки и прогресс чтения между устройствами через сервер.

## Состав

- `backend/` - Go HTTP API, миграции, admin CLI, работа с PostgreSQL и файловым хранилищем.
- `frontend/` - SolidJS SPA, статически отдается через nginx-контейнер.
- `api/openapi.yaml` - контракт HTTP API с endpoint-ами, схемами и ошибками.
- `docker-compose.yml` - PostgreSQL, backend, frontend/nginx, one-shot миграции и запуск admin CLI.

## Пользователи и доступ

Пользователь может зарегистрироваться через web UI, если публичная регистрация включена конфигурацией. Новый аккаунт активируется автоматически или администратором, в зависимости от настройки сервера.

Доступ к приватным разделам открывается после входа активного пользователя.

Администрирование выполняется через серверный CLI.

Admin CLI умеет:

- создавать пользователей;
- активировать и деактивировать пользователей;
- удалять пользователей;
- менять пароль;
- менять квоту;
- показывать список пользователей и статистику хранилища.

Доступ к CLI контролируется доступом к серверной консоли.

## Основные сценарии

Авторизованный пользователь работает с четырьмя основными разделами frontend:

- библиотека;
- загрузка книг;
- чтение книги;
- настройки аккаунта.

В библиотеке пользователь видит только свои книги, ищет по названию, фильтрует по тегам и избранному, сортирует список, открывает книгу, редактирует название/теги/избранное и удаляет книгу. Параметры списка библиотеки отражаются в query string URL, поэтому ссылку с поиском, тегами, сортировкой и фильтром избранного можно сохранить и открыть повторно. В рамках текущей работы SPA последний набор параметров списка также хранится во frontend-памяти и восстанавливается при возврате на `/library` без явных query-параметров.

На странице загрузки можно добавить несколько PDF/FB2 файлов за раз. Для каждой книги до отправки задаются название, теги и обложка. Frontend пытается извлечь обложку и название из файла, но пользователь может заменить их вручную.

В reader открываются PDF и FB2. Прогресс вычисляется frontend-ом по позиции прокрутки, сохраняется на сервере и восстанавливается при следующем открытии книги.

В настройках пользователь видит логин, статус аккаунта, занятую квоту, меняет язык интерфейса, меняет пароль и редактирует frontend-настройки как JSON object.

## Книги и метаданные

Поддерживаемые форматы книг:

- `pdf`;
- `fb2`.

Backend определяет формат книги по расширению имени загружаемого файла.

Пользовательская запись книги содержит:

- ссылку на физический файл;
- название;
- теги;
- признак избранного;
- обложку;
- даты создания и изменения;
- прогресс чтения.

Одинаковые названия разрешены. Теги хранятся в lowercase, принадлежат конкретному пользователю и очищаются после удаления последней связи с книгами этого пользователя.

Прогресс хранится отдельно от метаданных книги как процент `0..100`.

## Хранение файлов

Книги хранятся в локальной директории `BOOK_HUB_STORAGE_DIR`.

Физические файлы книг дедуплицируются по SHA-256 содержимого. Если два пользователя загрузили одинаковый файл, на диске лежит один файл, но в квоту каждого пользователя засчитывается полный размер этой книги.

Пара `пользователь - физический файл` уникальна в библиотеке.

При удалении книги удаляется пользовательская запись, ее теги-связи, прогресс и обложка. Физический файл книги удаляется с диска после удаления последней пользовательской ссылки на него.

Обложки хранятся отдельно от файлов книг. Backend сохраняет оригинал обложки и JPEG-миниатюру. Книжная квота пользователя считается по файлам книг.

## Квоты

У каждого пользователя есть лимит занимаемого объема. Значение по умолчанию задается конфигурацией, базовое значение - 2 GB.

Занятый объем считается как сумма размеров всех книг пользователя. Одинаковый физический файл засчитывается в квоту каждого пользователя, в чьей библиотеке он есть.

При загрузке книги backend проверяет, что текущий занятый объем плюс размер новой книги укладываются в квоту. Новая квота пользователя должна равняться уже занятому объему или превышать его.

## Настройки

Backend хранит frontend-настройки пользователя как opaque JSON object. Сервер валидирует тип и размер объекта.

Локальные настройки интерфейса хранятся в браузере. Серверные настройки используются для данных, доступных после входа с другого устройства.

## Безопасность

Аутентификация основана на server-side сессиях и cookie. В cookie хранится raw session token, в БД - его SHA-256 hash.

Пароли хранятся в виде Argon2id hash.

State-changing HTTP-запросы защищены CSRF double-submit схемой: readable CSRF cookie плюс `X-CSRF-Token`.

Все приватные операции проверяют активную сессию, активность пользователя и ownership ресурса. Ресурсы доступны владельцу пользовательской записи.

После смены пароля пользователем текущая сессия остается активной, остальные сессии отзываются. После смены пароля через CLI и деактивации пользователя отзываются все его сессии.

## Frontend

Frontend - SolidJS SPA с маршрутизацией на стороне клиента.

Основные маршруты:

- `/login`;
- `/register`;
- `/library`;
- `/upload`;
- `/reader/:bookId`;
- `/settings`.

Приложение работает same-origin с API. Base path задается при сборке/запуске и поддерживает размещение как с корня домена, так и из подпапки.

Клиент использует OpenAPI-generated TypeScript types для API-моделей, TanStack Query для серверного состояния и lazy loading для страниц/reader-компонентов.

PDF читается через PDF reader, FB2 - через собственный parser/layout/render pipeline во frontend. Backend отдает исходный файл после проверки доступа.

## Backend

Backend - Go HTTP server с явным SQL-доступом к PostgreSQL через repository/storage слой.

Основные зоны ответственности backend:

- регистрация, login/logout, текущий пользователь и смена пароля;
- проверка сессий, CSRF и ownership;
- CRUD пользовательских книг и метаданных;
- загрузка, дедупликация и удаление файлов книг;
- загрузка, миниатюризация и удаление обложек;
- учет квот;
- хранение прогресса чтения;
- хранение opaque frontend-настроек;
- health/readiness checks.

Миграции запускаются отдельной командой.

## База данных

PostgreSQL хранит:

- пользователей;
- дедуплицированные физические файлы книг;
- пользовательские записи книг;
- теги и связи книг с тегами;
- прогресс чтения;
- server-side сессии;
- JSON-настройки пользователя.

UUID генерируются приложением. Timestamps хранятся в UTC.

## Развертывание

Типовой запуск выполняется через Docker Compose:

- PostgreSQL хранит данные в persistent volume;
- backend доступен только внутри Docker network;
- frontend/nginx публикуется наружу и проксирует API-запросы в backend;
- миграции запускаются one-shot сервисом;
- admin CLI запускается отдельной `docker compose run` командой.

Для production обычно ставится внешний reverse proxy с TLS перед frontend/nginx. При HTTPS-размещении session и CSRF cookie должны работать с `Secure`.

Бэкап должен включать PostgreSQL dump и директорию файлового хранилища, согласованные по времени.
