# Book Hub

Book Hub - приватное self-hosted веб-приложение для хранения личной библиотеки и чтения книг в браузере.

## Назначение

Приложение решает три задачи:

- хранит пользовательские PDF, DJVU, FB2 и EPUB книги;
- дает веб-интерфейс для загрузки, каталогизации и чтения;
- синхронизирует метаданные, настройки и прогресс чтения между устройствами через сервер.

## Состав

- `backend/` - Go HTTP API, миграции, admin/backup CLI, работа с PostgreSQL или SQLite и файловым хранилищем.
- `frontend/` - SolidJS SPA, статически отдается через nginx-контейнер или опционально Go-сервер.
- `api/openapi.yaml` - контракт HTTP API с endpoint-ами, схемами и ошибками.
- `docker-compose.yml` - стек PostgreSQL; `docker-compose.sqlite.yml` - стек SQLite без PostgreSQL;
  оба запускают backend, frontend/nginx и отдельные CLI.

## Пользователи и доступ

Пользователь может зарегистрироваться через web UI, если публичная регистрация включена конфигурацией. Новый аккаунт активируется автоматически или администратором, в зависимости от настройки сервера.

Доступ к приватным разделам открывается после входа активного пользователя. При переходе на приватную страницу без сессии пользователь попадает на `/login`, а после входа возвращается на исходную страницу. Если регистрация сразу активирует аккаунт, вход выполняется автоматически. Если сессия истекла во время работы, приватный кэш frontend сбрасывается и открывается страница входа.

Временная занятость SQLite возвращает `503 service_unavailable`, включая проверку авторизации, и не сбрасывает
сессию. При первом запросе текущего пользователя frontend показывает ошибку с повтором; при наличии данных
пользователя временный сбой повторной проверки сохраняет доступ к странице.

Администрирование выполняется через серверный CLI. Создаваемые через него пользователи активируются сразу.

Admin CLI умеет:

- создавать пользователей;
- активировать и деактивировать пользователей;
- удалять пользователей;
- менять пароль;
- менять квоту;
- показывать список пользователей и статистику хранилища.

Доступ к CLI контролируется доступом к серверной консоли.

## Основные сценарии

Авторизованный пользователь работает с четырьмя основными разделами frontend:

- библиотека;
- загрузка книг;
- чтение книги;
- настройки аккаунта.

В библиотеке пользователь видит только свои книги, ищет по названию или описанию, фильтрует по тегам и избранному, сортирует список, переключает вид отображения (список или сетка обложек), открывает книгу, редактирует название/описание/теги/избранное/обложку и удаляет книгу. Действия книги доступны через меню: в списке оно открывается шевроном или правым кликом по обложке, в сетке — шевроном или правым кликом по карточке. Меню позволяет изменить избранное, метаданные, сбросить прогресс, показать полную обложку, скачать файл книги или удалить книгу. Параметры списка библиотеки (поиск, поле поиска, теги, сортировка, фильтр избранного) отражаются в query string URL, поэтому ссылку можно сохранить и открыть повторно. Режим отображения (список/сетка) в URL не попадает — это локальная настройка браузера. Последний набор параметров списка также хранится во frontend-памяти и восстанавливается при возврате на `/library` без явных query-параметров. Ссылки «Библиотека», логотип и возврат из читалки включают текущие параметры списка; повторный переход в библиотеку сохраняет фильтры и query string.

Удаление книги и сброс её прогресса подтверждаются модальным окном с полным названием книги. Кнопки — «Удалить» или «Сбросить прогресс» и «Отмена»; начальный фокус на отмене. Escape и клик по фону закрывают окно без действия. Во время запроса кнопки заблокированы, при ошибке окно остаётся открытым для повтора.

В формах создания и редактирования закладки используется та же строка поиска с выбором поля и кнопкой очистки, что и в библиотеке. Очистка меняет только черновик закладки.

Личные закладки сохраняют название, поиск, поле поиска и теги в серверных настройках пользователя (`libraryBookmarks`); они доступны между сеансами и устройствами. В боковом меню закладки находятся под разделителем, список прокручивается отдельно от основных пунктов, кнопки «Создать закладку», языка и выхода. Пункты закладок имеют иконку закладки слева; отступы, размер иконок и выравнивание текста совпадают с основным меню. Кнопка с плюсом слева оформлена как пункт меню и расположена сразу после закладок, при пустом списке — первой. На мобильном экране кнопка «Закладки» открывает отдельный диалог. Создание копирует последние фильтры библиотеки в независимый черновик (до первого посещения — пустой поиск по названию и без тегов) и не меняет выдачу. При открытии формы создания название предзаполняется текстом поиска и выбранными тегами через пробел, с обрезкой до 100 символов; при пустых фильтрах — «Закладка». Фокус устанавливается в поле названия с выделением всего текста для быстрой замены. Название обрезается по краям, обязательно и ограничено 100 символами; одинаковые названия и фильтры допустимы. Применение полностью заменяет поиск и теги, сохраняет текущий фильтр избранного, сортировку и вид, возвращает к началу выдачи. Выбранная закладка подсвечивается; её ID сохраняется локально в браузере и восстанавливается после перезагрузки. Выбор сбрасывается при изменении текста или поля поиска, тегов (включая очистку фильтров), удалении закладки или изменении её поисковых параметров. Изменение и очистка только фильтра избранного сохраняют выбор закладки. При уходе из библиотеки подсветка закладки скрывается, а её выбор сохраняется. При возврате в библиотеку через меню или историю браузера подсветка восстанавливается, если поисковые параметры закладки по-прежнему совпадают с сохранёнными фильтрами библиотеки. Это относится ко всем разделам, включая читалку. Подсветка при наведении плавно появляется и затухает на всей строке, включая область кнопки редактирования. Кнопка редактирования справа от закладки появляется при наведении, с клавиатуры при фокусе, на сенсорном экране — после длительного нажатия. Пока кнопка скрыта, название занимает всю доступную ширину строки без резерва под неё. Редактирование открывает форму с текущим названием, поиском, полем поиска и тегами; сохранение обновляет закладку на прежнем месте и не меняет выдачу. Кнопка «Удалить» находится слева внизу формы редактирования; удаление подтверждается диалогом с полным названием и кнопками «Да» / «Нет» и не меняет выдачу. Отмена подтверждения возвращает к черновику редактирования. Порядок закладок меняется перетаскиванием за левую иконку с анимацией перемещения и сохраняется в серверных настройках. При фокусе на иконке порядок также меняется стрелками вверх и вниз. Вся область между иконкой и кнопкой редактирования открывает закладку, включая свободное место после короткого названия. При ошибке сохранения восстанавливается прежний порядок и показывается сообщение об ошибке.

Первый пункт меню книги «Информация о книге» открывает компактное окно с обложкой слева, названием, описанием (если заполнено) и кликабельными тегами. Клик по обложке в окне информации открывает существующий просмотр полной обложки; после его закрытия снова показывается информация о книге. В сетке кнопка ⓘ справа внизу карточки появляется при наведении или фокусе с клавиатуры, как кнопка меню (на сенсорных устройствах обе видны постоянно), и за один клик открывает панель с названием, описанием и тегами без обложки. Клик по тегу закрывает окно или панель и добавляет тег в текущий фильтр без дубликатов, сохраняя остальные параметры поиска. Окно и панель закрываются кнопкой, Escape или кликом снаружи.

В режиме списка под названием книги отображается описание, если оно заполнено, а ниже — теги. Переносы строк в описании сохраняются. Описание длиннее двух строк сворачивается до двух строк с кнопкой «…» в конце; после раскрытия описание показывается целиком, а кнопка исчезает. Клик по тегу добавляет его в текущий фильтр тегов без дубликатов, сохраняя остальные параметры поиска. Книга открывается кликом по обложке или заголовку; заголовок подсвечивается только при наведении на него.

Поле тегов используется в фильтре библиотеки, редакторе книги и черновиках загрузки. Подсказки учитывают текущий ввод и исключают выбранные теги; недавно использованные варианты показываются первыми. Тег выбирается кликом или стрелками и Enter. Введённый текст добавляется по Enter или при уходе фокуса из поля; пробелы по краям удаляются, регистр приводится к нижнему, дубликаты исключаются. Доступно до 50 тегов по 64 символа Unicode. Непоместившиеся теги доступны через «+N». Пара последовательных Backspace в пустом поле удаляет последний тег; если он скрыт, первая пара раскрывает список. Escape закрывает список и возвращает фокус в поле.

При раскрытой группе Tab проходит от «+N» по кнопкам удаления скрытых тегов к инпуту; Shift+Tab идёт обратно. Внутренние переходы сохраняют группу и незавершённый ввод, следующий Tab из инпута покидает поле и применяет текст. Enter или Пробел на кнопке удаления удаляет один тег и переводит фокус к следующему, а при его отсутствии — к предыдущему; после удаления всех тегов фокус возвращается в инпут. Удержание Enter не удаляет несколько тегов. Изменение ширины и внешнее обновление выбранных тегов сохраняют фокус на том же теге или соседнем, если он удалён. Escape сохраняет незавершённый текст, а клик за пределами поля применяет его.

В интерфейсе доступны три варианта сортировки: релевантная (по умолчанию), название А-Я, название Я-А.
API также поддерживает `created_at_desc` — от новых книг к старым. Релевантная сортировка использует
`last_opened_at DESC, created_at DESC, id DESC`; для остальных сортировок равенство основных ключей разрешается
через `id DESC`. Селект слева внутри строки поиска выбирает поле: «По названию» (по умолчанию) или «По описанию». Выбор сохраняется в URL как `search_field=description` и при возврате в библиотеку. Поиск в выбранном поле ищет буквальную подстроку без учёта регистра, включая кириллицу и латиницу;
`%`, `_` и `\` не являются шаблонами, `е` и `ё` различаются. Алфавитный порядок отдельных символов может
различаться между СУБД. При сеточном виде отображаются только обложки; при отсутствии обложки на её месте
показывается название. При наведении на обложку в сетке и списке появляется стандартная браузерная подсказка с названием книги. Правый клик по карточке подавляет стандартное меню браузера и открывает меню действий книги.

На странице загрузки можно добавить несколько PDF/DJVU/FB2/EPUB файлов за раз. Для каждой книги до отправки задаются название, описание, теги и обложка. Для пачки из двух и более книг общие теги добавляются к тегам каждой книги. Frontend пытается извлечь обложку и название из файла, но пользователь может заменить их вручную. EPUB до отправки проверяется как адаптивная книга без DRM; DJVU проверяется как bundled-документ с доступной первой страницей. Повреждённый, неподдерживаемый или многофайловый DJVU не загружается. Для DJVU обложкой служит первая страница, а название извлекается только из явных метаданных. Ошибка обложки не отменяет добавление валидной книги. При частичной ошибке успешно добавленные книги исчезают из списка, а у неудачных показывается причина ошибки. Во время последовательной отправки пачки из двух и более книг отображается прогресс; страница блокируется до завершения всех попыток.

В области выбора файлов показываются свободное место по квоте пользователя и суммарный размер оставшихся черновиков. Учитываются только файлы книг, без обложек. Значения пересчитываются при добавлении и удалении файлов; после попытки отправки пачки данные квоты запрашиваются заново. Если суммарный размер превышает свободное место, показывается предупреждение с размером нехватки; сравнение выполняется в байтах до округления. Предупреждение не блокирует частичную загрузку пачки, окончательную проверку квоты выполняет backend. При ошибке получения квоты показывается сообщение о недоступности данных вместо свободного места.

При редактировании метаданных книги можно заново извлечь обложку из файла: книга скачивается с сервера, и frontend переиспользует ту же логику извлечения обложки, что и при загрузке.

В формах добавления и редактирования сразу под названием находится необязательное описание.

Окно редактирования книги имеет ширину до 960 px и адаптируется к экрану. Не поместившиеся в поле теги доступны через кнопку «+N».
Его вводят вручную обычным текстом; описание отображается в списке книг и доступно для поиска в режиме «По описанию». Поиск по описанию использует сохранённые метаданные, а не содержимое файла книги.
Поле автоматически растёт и уменьшается от высоты однострочного инпута до десяти видимых строк,
включая переносы по ширине; затем появляется вертикальная прокрутка. Высота сразу учитывает
предзаполненный текст и пересчитывается при изменении ширины. Ручное растягивание отключено.
Лимит ввода и серверной проверки — 10 000 единиц UTF-16; при вставке принимается только
помещающаяся часть текста. При сохранении пробельные края удаляются, внутренние переносы
и пустые строки сохраняются. Очистка поля удаляет описание. У каждого черновика загрузки
своё описание, которое сохраняется при неудачной попытке загрузки.

В reader открываются PDF, DJVU, FB2 и адаптивные EPUB без DRM. PDF и DJVU используют общие управление шириной страницы, увеличение ширины, фильтры, оглавление, поиск и прогресс. PDF растеризует длинные страницы горизонтальными полосами и рисует только полосы рядом с областью чтения, сначала ближайшие к ней; рендеры, ушедшие из этой области при быстром переходе, отменяются, а текстовый слой строится после изображения. DJVU отрисовывает только страницы в текущей области чтения, сначала ближайшие к её центру; пропущенные при быстром переходе страницы отрисовываются при возврате к ним. DJVU использует встроенное NAVM-оглавление; внутренние ссылки ведут к странице, внешние открываются в новой вкладке. OCR-текст DJVU доступен для поиска, выделения и копирования; без текстового слоя поле поиска остаётся доступным, но совпадений не будет. EPUB и FB2 используют общую виртуализированную читалку, непрерывную прокрутку и единые локальные настройки цветов, шрифта, интервалов и ширины текста. Прогресс вычисляется frontend-ом по позиции прокрутки, сохраняется на сервере и восстанавливается при следующем открытии книги.

В боковой панели «Внешний вид» книг с фиксированной вёрсткой (PDF и DJVU) есть подраздел «Страница» с ползунком увеличения ширины `0..80%`. Он расширяет страницу симметрично относительно центра после расчёта ручной или автоматической ширины, сохраняя её пропорции. При автоширине и ручной ширине, ограниченной viewport, ненулевое увеличение рассчитывается от фактической ширины viewport, поэтому положение содержимого относительно его краёв не меняется при изменении окна. Значение хранится отдельно для каждой книги; ширина, заданная направляющими, остаётся общей настройкой таких читалок. Если появляется горизонтальная прокрутка, при открытии книги и любом изменении ширины страницы восстанавливается сохранённая пользователем относительная позиция. Позиции в центре и у левого края не сохраняются — для них используется центрирование.

В настройках пользователь видит имя аккаунта, занятую квоту, выбирает цветовую тему, может сбросить прогресс чтения всех книг и меняет пароль.

В окне и компактной панели информации о книге длинные теги отображаются в одну строку
с многоточием; полное название доступно при наведении. При выборе используется полный тег.

В настройках читалки FB2/EPUB размер шрифта регулируется от 14 до 90 px, интерлиньяж — от 1,0 до 2,2, отступ первой строки — от 0 до 256 px, отступ после абзаца — от 4 до 120 px.

## Навигация в читалке

Во всех форматах книг короткий тап в средней половине экрана по высоте переключает верхнюю и нижнюю панели. Движение пальца не запускает управление наведением мыши. В правой трети экрана тап в верхней четверти прокручивает книгу назад, в нижней четверти — вперёд на 90% высоты окна с сохранением видимости панелей. Свайпы, масштабирование несколькими пальцами, долгие нажатия, выделение текста и тапы по ссылкам не запускают эти действия.

Кнопки верхней панели читалки используют единый компактный размер.

Сразу после названия книги кнопка «Информация о книге» открывает общий с библиотекой диалог
с обложкой, названием, описанием и тегами. Клик по обложке открывает её полный просмотр;
после закрытия просмотра снова показывается информация. Клик по тегу закрывает диалог
и открывает библиотеку, добавляя тег в текущий фильтр без дубликатов и сохраняя остальные параметры поиска.

Боковые панели настроек и оглавления имеют компактную шапку; кнопка закрытия размером 32 × 32 px отображается без видимой рамки, с фоном при наведении.

В нижней части панели настроек кнопки сброса и автоширины имеют высоту 32 px и расположены в один ряд с компактными отступами.

Блоки фильтров PDF и DJVU используют компактные отступы, малоконтрастные рамки и небольшие кнопки перетаскивания.

Параметры фильтров отображаются с небольшими подписями, значениями с одинаковой шириной цифр и тонкими ползунками.

Линейка ширины во всех форматах книг — компактная шкала высотой 18 px с малоконтрастными делениями и небольшими акцентными маркерами границ.

Справа в нижней панели читалки кнопка с иконкой переключает тонкие малоконтрастные полосы прокрутки страницы в обоих направлениях. Кнопка скрыта на устройствах с основным указателем низкой точности (например, сенсорным экраном), независимо от ширины окна. Фон полос совпадает с фоном области чтения, цвет ползунка берётся из темы. В браузерах с поддержкой `::-webkit-scrollbar` толщина составляет 1 px, в остальных используется системный тонкий вариант. По умолчанию режим выключен; выбор сохраняется только в браузере и применяется ко всем форматам книг.

Переходы по внутренним ссылкам и пунктам оглавления сохраняются в истории браузера: кнопки «Назад» и «Вперёд» возвращают к соответствующим актуальным местам чтения.

Меню книги содержит три группы: информация, просмотр обложки и скачивание; избранное, редактирование и сброс прогресса; удаление. Группы отделены разделителями.

## Книги и метаданные

Поддерживаемые форматы книг:

- `pdf`;
- `fb2`;
- `epub` (адаптивный EPUB 2/3 без DRM).

Backend определяет формат книги по расширению имени загружаемого файла.

Пользовательская запись книги содержит:

- ссылку на физический файл;
- название;
- необязательное описание;
- теги;
- признак избранного;
- обложку;
- даты создания и изменения;
- прогресс чтения.

Одинаковые названия разрешены. Пробелы по краям тегов удаляются, буквы приводятся к нижнему регистру.
Теги принадлежат конкретному пользователю и очищаются после удаления последней связи с книгами этого пользователя.
Фильтрация требует точного совпадения всех выбранных нормализованных тегов.

## Хранение файлов

Для всей библиотеки выбирается одно хранилище оригиналов через `BOOK_HUB_BOOK_STORAGE`: локальная директория
(`directory`), FTP (`ftp`), explicit FTPS (`ftps-explicit`), implicit FTPS (`ftps-implicit`) или S3 (`s3`). FTP-подключение и выделенная область задаются `BOOK_HUB_FTP_ADDR`,
`BOOK_HUB_FTP_USER`, `BOOK_HUB_FTP_PASSWORD` и `BOOK_HUB_FTP_ROOT`; изображения остаются локальными.
Оба FTPS-режима шифруют соединения и проверяют сертификат и имя сервера; дополнительный доверенный
CA задаётся через `BOOK_HUB_FTP_CA_FILE`. Переход на незашифрованный FTP при ошибке TLS не выполняется.
S3 использует заданные endpoint, регион, бакет, префикс и серверные учётные данные; для Amazon S3 endpoint
необязателен. Проверен Garage v2.5.0. Браузер получает файлы через backend; оригинал публикуется после
успешного сохранения; при чтении проверяется размер без вычисления SHA-256.
Директории оригиналов (`BOOK_HUB_BOOKS_DIR`), локальных изображений (`BOOK_HUB_IMAGES_DIR`) и рабочих файлов
(`BOOK_HUB_WORK_DIR`) задаются независимо. Без этих настроек сохраняется прежняя структура `books`, `covers` и `tmp`
под `BOOK_HUB_STORAGE_DIR`, включая старые абсолютные и относительные ссылки на файлы.

Чтение и скачивание проходят через backend после проверки прав. Перед выдачей проверяется размер оригинала
без вычисления SHA-256, в том числе при выключенном кэше и при его заполнении. Удалённый источник сначала
целиком сохраняется в рабочую директорию. Локальный оригинал выдаётся напрямую без предварительного чтения
содержимого. Сохраняются HEAD, частичные и условные запросы, MIME-тип и Unicode-имя файла.
Недоступность оригинала, ошибка передачи или несовпадение размера возвращает `503 service_unavailable`
и сохраняет сессию. Изменение содержимого с сохранением размера при чтении не обнаруживается.

Временные файлы загрузки новых книг и получения оригиналов используют общий лимит `BOOK_HUB_WORK_MAX_BYTES`,
по умолчанию 1 ГиБ на backend. При нехватке места новая операция получает временную ошибку; текущие выдачи
продолжаются. Файлы и резервы освобождаются после использования, ошибки или отмены. При запуске удаляются
незавершённые рабочие файлы предыдущего процесса. Рабочая директория у каждого backend своя; место для backup
учитывается отдельно. Проверки запуска и готовности не обращаются к оригиналам, а проверяют БД, изображения и
рабочую директорию.

Необязательный кэш целых файлов книг включается парой `BOOK_HUB_CACHE_DIR` и `BOOK_HUB_CACHE_MAX_BYTES`.
По умолчанию он выключен. Чтение и скачивание используют одну копию одинакового файла на backend; при попадании
оригинал не читается и не проверяется. Права доступа проверяются при каждом запросе. Готовые копии переживают
перезапуск; при запуске проверяются локально, а незавершённые и повреждённые файлы удаляются. Уже проверенная
копия не хешируется заново при каждой выдаче.

Кэш вытесняет давно не используемые копии по LRU и защищает активные выдачи. Его строгий лимит учитывает готовые
файлы и полные резервы получаемых файлов. После успешной загрузки сохраняется уже принятый файл без обратного
получения оригинала. Если кэш выключен, неисправен, занят активными выдачами или книга превышает лимит, локальный
оригинал выдаётся напрямую, удалённый — через ограниченную рабочую директорию. Ошибка кэша записывается в лог
и не отменяет сохранённую книгу. Кэшированные книги доступны при недоступных оригиналах.

Одновременные запросы одинакового исходного файла на одном backend используют одно получение как в кэш,
так и в рабочую директорию. Каждый запрос сохраняет собственный диапазон и позицию чтения. Отмена одного
клиента не мешает остальным; при уходе всех ожидающих незавершённое получение отменяется. Новый запрос
ожидает освобождения ресурсов отменённого получения, а готовый общий файл остаётся до завершения последней выдачи.

Физические файлы книг дедуплицируются по SHA-256 содержимого. Если два пользователя загрузили одинаковый файл, на диске лежит один файл, но в квоту каждого пользователя засчитывается полный размер этой книги.

Пара `пользователь - физический файл` уникальна в библиотеке.

При удалении книги сразу удаляются пользовательская запись, её теги-связи, прогресс и локальная обложка. После последней пользовательской ссылки удаление оригинала сохраняется в очереди БД и выполняется backend в фоне с повтором после сбоев. Удаление пользователя через admin CLI использует ту же очередь; при остановленном backend задача ждёт следующего запуска. Повторная загрузка того же содержимого защищена от старой задачи удаления.
Ошибка удаления отдельного оригинала не блокирует остальные задачи: обработчик проходит очередь пакетами,
а неудачные задачи сохраняет для следующего прохода.

Обложки хранятся отдельно от файлов книг. Backend сохраняет оригинал обложки и JPEG-миниатюру. Книжная квота пользователя считается по файлам книг.

## Квоты

У каждого пользователя есть лимит занимаемого объема. Значение по умолчанию задается конфигурацией, базовое значение - 2 GB.

Занятый объем считается как сумма размеров всех книг пользователя. Одинаковый физический файл засчитывается в квоту каждого пользователя, в чьей библиотеке он есть.

При загрузке книги backend проверяет, что текущий занятый объем плюс размер новой книги укладываются в квоту. Новая квота пользователя должна равняться уже занятому объему или превышать его.

## Настройки

Backend хранит frontend-настройки пользователя как opaque JSON object. Сервер валидирует тип и размер объекта.

Локальные настройки интерфейса хранятся в браузере. Серверные настройки используются для данных, доступных после входа с другого устройства. К локальным относятся: язык интерфейса, цветовая тема, режим отображения библиотеки (список/сетка), настройки читалок (FB2 и фиксированной вёрстки PDF/DJVU), недавние теги.

## Цветовые темы

Приложение поддерживает несколько цветовых тем: несколько светлых и несколько тёмных. Цвета реализованы через семантические CSS custom properties, переопределяемые под каждую тему через атрибут `data-theme` на корневом элементе; компонентные стили используют эти токены напрямую.

Тема — локальная настройка браузера. По умолчанию используется тема «Песок» для светлого системного оформления и «Чернила» для тёмного (`prefers-color-scheme`), далее выбор пользователя сохраняется. Неизвестная сохранённая тема заменяется на тему по умолчанию. Активная тема применяется инлайн-скриптом в `index.html` до первого рендера, чтобы избежать мигания темы. Зона читалки (FB2/PDF/DJVU) изолирована: цвет фона, текста и ссылок в ней задаётся отдельными настройками читалки и не зависит от темы приложения.

## Прогресс чтения

Прогресс хранится в сущности пользовательской книги как процент `0..100`. Там же хранится `last_opened_at`: время последнего успешного сохранения прогресса; по умолчанию оно равно времени добавления книги. Сортировка `relevance` использует `last_opened_at` по убыванию.

При открытии книги этот процент используется для начального позиционирования: frontend ждёт стабилизации высоты документа и прокручивает к позиции, пока читалка закрыта индикатором загрузки. Прокрутка, начатая пользователем, прерывает восстановление. Сохранение прогресса включается только после завершения восстановления. При изменении ширины окна, ширины текста, настроек шрифта, интерлиньяжа, отступов или при сбросе настроек читалка сохраняет видимый текстовый якорь: тот же блок остаётся на том же месте экрана. Эти действия не должны прокручивать книгу; текущую позицию меняет только пользовательская прокрутка.

После загрузки веб-шрифтов читалка FB2/EPUB сбрасывает кэш измерений текста и пересчитывает высоты блоков, чтобы строки не обрезались из-за метрик запасного шрифта.

Помимо прогресса отдельной книги, доступен атомарный сброс прогресса всех книг пользователя (`DELETE /v1/me/progress`); сброс устанавливает процент в `0` и не меняет `last_opened_at`.

## Безопасность

Аутентификация основана на server-side сессиях и cookie. В cookie хранится raw session token, в БД - его SHA-256 hash.

Пароли по умолчанию хранятся в виде Argon2id hash (64 МиБ, 3 прохода, параллелизм 2). Настройка `BOOK_HUB_PASSWORD_ALGORITHM=pbkdf2-sha256` включает PBKDF2-HMAC-SHA256 с 600 000 итераций без большого рабочего буфера. Оба формата содержат случайную 16-байтную соль, параметры и 32-байтный ключ; проверка поддерживает оба алгоритма независимо от настройки. Сервер и admin CLI используют выбранный алгоритм при создании и смене пароля. При успешном входе активного пользователя хеш другого алгоритма заменяется на выбранный без отзыва сессий; параллельная смена пароля не перезаписывается. Первый вход после переключения ещё использует старый алгоритм для проверки.

Число итераций PBKDF2 настраивается через `BOOK_HUB_PBKDF2_ITERATIONS` (по умолчанию 600 000, диапазон 1–10 000 000). Меньшие значения снижают нагрузку на CPU и устойчивость к подбору. При успешном входе хеш с другим числом итераций обновляется до настройки сервера; первая проверка использует прежнюю стоимость. Сервер и admin CLI применяют настройку при создании и смене пароля.

State-changing HTTP-запросы защищены CSRF double-submit схемой: readable CSRF cookie плюс `X-CSRF-Token`.

Все приватные операции проверяют активную сессию, активность пользователя и ownership ресурса. Ресурсы доступны владельцу пользовательской записи.

После смены пароля пользователем текущая сессия остается активной, остальные сессии отзываются. После смены пароля через CLI и деактивации пользователя отзываются все его сессии.

## Frontend

Frontend - SolidJS SPA с маршрутизацией на стороне клиента.

Интерфейс использует общую дизайн-систему: стандартные поля, селекты и кнопки имеют высоту
40 px, компактные контролы — 32 px; типографика, отступы, поверхности и состояния согласованы
между страницами и панелями читалок. Восемь цветовых тем используют семантические токены.
Правила и способы проверки описаны в [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md).

HTML приложения отдаётся без кэширования; отсутствующие файлы сборки возвращают 404 без подмены HTML. При ошибке динамического импорта frontend запрашивает свежий HTML и сравнивает адрес основного модуля. Если на сервере другая сборка, текущий URL открывается с параметром обхода кэша, который затем удаляется. Автоматический переход ограничен одной попыткой на сборку в рамках вкладки; при недоступном sessionStorage, сетевой ошибке или неизменившейся сборке сохраняется обычная обработка ошибки.

Основные маршруты:

- `/login`;
- `/register`;
- `/library`;
- `/upload`;
- `/reader/:bookId`;
- `/settings`.

Приложение работает same-origin с API. Base path задается при сборке/запуске и поддерживает размещение как с корня домена, так и из подпапки.

Клиент использует OpenAPI-generated TypeScript types для API-моделей, TanStack Query для серверного состояния и lazy loading для страниц/reader-компонентов.

PDF и DJVU читаются во frontend как книги с фиксированной вёрсткой, а FB2 и EPUB — через общий parser/layout/render pipeline. Backend отдает исходный файл после проверки доступа. При декодировании FB2 учитывается кодировка из XML-декларации (UTF-8 по умолчанию, windows-1251 и др.), чтобы корректно читались файлы в legacy-кодировках. EPUB перед обработкой проверяется и распаковывается во frontend.

Для рендеринга PDF frontend раздает статические ресурсы pdf.js (WASM-декодеры, стандартные шрифты, CMap'ы) из `public/pdfjs-assets/` по пути `<base>/pdfjs-assets/`. Worker pdf.js собирается Vite как отдельный ES-модуль вместе с полифиллами (`src/polyfills/esnext.ts`) для API, которых ещё нет в части браузеров. Файлы синхронизируются из `pdfjs-dist` скриптом `scripts/sync-pdfjs-assets.mjs` при `npm install` и сборке. Для DJVU аналогично синхронизируется проверенный bundle DjVu.js в `public/djvujs-assets/djvu.js`; он загружается только при открытии DJVU. Настройки фильтров фиксированной вёрстки хранятся локально в browser preferences, а WebGL-фильтр рисует результат в отдельный canvas; исходный canvas и текстовый слой не изменяются.
Размеры и смещения растровых полос PDF задаются по разрешению canvas с учётом плотности экрана, без дополнительного растяжения до пропорций контейнера страницы. Встроенный текст PDF можно выделять и копировать; страницы без встроенного текстового слоя, включая сканы, недоступны для текстового выделения.

## Backend

Backend - Go HTTP server с явным SQL-доступом к PostgreSQL или SQLite через repository/storage слой.

Необязательный `BOOK_HUB_FRONTEND_DIR` включает публичную выдачу готовой production-сборки тем же
HTTP-сервером. Путь абсолютный либо относительно рабочего каталога процесса; по умолчанию раздача выключена.
Перед запуском проверяется читаемость каталога и обычного `index.html`; административные команды от него не зависят.
Frontend доступен под `BOOK_HUB_BASE_PATH`, API сохраняет приоритет под тем же префиксом с `/api`.
Корень подпути без слеша перенаправляется со статусом `308` с сохранением query string.
Для отсутствующих страниц без расширения выдаётся `index.html`; отсутствующие ресурсы, скрытые файлы,
каталоги и пути за пределами сборки возвращают `404`. Статическая ветка поддерживает `GET` и `HEAD`,
прочие методы получают `405`. HTML не кэшируется и не возвращает `304`; ресурсы Vite с хэшем могут иметь
`immutable`, остальные файлы требуют перепроверки. Сборка заранее выполняется с соответствующим `VITE_BASE_PATH`.

Основные зоны ответственности backend:

- регистрация, login/logout, текущий пользователь и смена пароля;
- проверка сессий, CSRF и ownership;
- CRUD пользовательских книг и метаданных;
- загрузка, дедупликация и удаление файлов книг;
- загрузка, миниатюризация и удаление обложек;
- учет квот;
- хранение прогресса чтения;
- хранение opaque frontend-настроек;
- health/readiness checks.

Миграции запускаются отдельной командой.
Сервер обрабатывает SIGINT и SIGTERM для штатной остановки.

## База данных

Выбранная СУБД хранит:

- пользователей;
- дедуплицированные физические файлы книг;
- пользовательские записи книг;
- теги и связи книг с тегами;
- прогресс чтения;
- server-side сессии;
- JSON-настройки пользователя.

UUID генерируются приложением. Timestamps хранятся в UTC.

Обязательная настройка `BOOK_HUB_DATABASE_URL` определяет СУБД: `postgres://`/`postgresql://` или
`sqlite:///абсолютный/путь`. SQLite работает с одним backend на локальном диске; многопользовательский доступ
сохраняется. Для нескольких экземпляров backend требуется PostgreSQL. Они используют общие оригиналы и локальные
изображения, но отдельные кэши, рабочие каталоги и бюджеты. Права проверяются по общей БД перед каждой выдачей;
кэш другого экземпляра не сохраняет доступ к удалённой записи. SQLite использует WAL, внешние ключи
и `synchronous=FULL`. Сервер и admin CLI открывают только существующую базу с актуальной завершённой схемой;
создание SQLite-файла и миграции выполняются отдельным мигратором.

## Развертывание

Типовой запуск выполняется через Docker Compose:

- PostgreSQL или SQLite хранит данные в отдельном persistent volume;
- backend доступен только внутри Docker network;
- frontend/nginx публикуется наружу и проксирует API-запросы в backend;
- миграции запускаются one-shot сервисом;
- admin CLI запускается отдельной `docker compose run` командой.

Стандартные каталоги кэша `/data/cache` и рабочих файлов `/data/books/tmp` подключены только к backend
через отдельные anonymous volumes на контейнер. Кэш остаётся выключенным до явного задания пути и лимита.
Оригиналы и изображения используют общий постоянный volume; для отдельных дисков и нескольких backend
администратор задаёт соответствующие общие и индивидуальные mounts.

Для production обычно ставится внешний reverse proxy с TLS перед frontend/nginx. При HTTPS-размещении session и CSRF cookie должны работать с `Secure`.

Make выбирает Compose-стек по URL подключения. В SQLite-стеке PostgreSQL не запускается и `POSTGRES_*` не нужны.
Перед миграциями, резервным копированием и восстановлением приложение останавливается; другие CLI-процессы
не должны выполнять записи в это время. Admin CLI может работать одновременно с сервером вне обслуживания.

Новая резервная копия содержит `manifest.json` с версией формата, СУБД и версией схемы,
`database.sql` либо `database.sqlite` и `storage.tar.gz` с книгами и обложками. SQLite-снимок включает WAL.
Копия собирает все используемые оригиналы из выбранной директории, FTP, обоих режимов FTPS или S3 и локальные изображения; кэш и рабочие
файлы в неё не входят. Размер и SHA-256 книг проверяются при копировании и восстановлении.
Каталог изображений может быть задан симлинком; при копировании используется его целевой каталог.
Симлинки внутри дерева изображений отклоняются.
Старые поддерживаемые копии, включая PostgreSQL без manifest, восстанавливаются с пересчётом путей оригиналов и изображений.
До изменения назначения проверяются формат, СУБД, целостность архива и пустота выделенной директории или
удалённой области оригиналов; соседние области не очищаются. Тип хранилища можно сменить через backup,
перенастройку и restore без исходного сервиса. Формат комплекта копии от типа хранилища не зависит;
перенос между СУБД не поддерживается. Restore применяет необходимые штатные миграции старой схемы.
После успешного backup/restore приложение запускается; ошибка после остановки оставляет его выключенным.
После сбоя restore администратор очищает выделенное назначение и повторяет операцию из того же архива;
автоматического продолжения или отката нет.
